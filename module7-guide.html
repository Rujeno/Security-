Application Security and Time Synchronization

Explaining Application Services — TLS · NTP · PTP

TLS (Transport Layer Security) يوفر ثلاث خصائص أساسية:

TLS (Transport Layer Security) provides three core properties:

  • Encryption: تشفير البيانات.
  • Authentication: تأكيد هوية السيرفر عبر الشهادات (certificates).
  • Integrity: التأكد أن البيانات لم تتغيّر أثناء النقل.
  • Encryption: encrypting the data.
  • Authentication: confirming the server's identity via certificates.
  • Integrity: confirming the data wasn't altered in transit.

TLS Handshake:

Client Hello←Server Hello←Client Key Exchange←Session Key Established←Server Finished

NTP (Network Time Protocol): يزامن ساعات الأنظمة مع UTC عبر بروتوكول UDP على المنفذ 123.

NTP (Network Time Protocol): synchronizes system clocks with UTC over UDP on port 123.

  • Hierarchy: ينظّم الأجهزة هرميًا حسب بُعدها عن الساعة المرجعية (stratum).
  • Synchronization: يزامن الأجهزة عبر رسائل مُختَّمة زمنيًا (timestamped) بين الأقران.
  • Algorithms: يستخدم خوارزميات معقدة لحساب تأخير الشبكة والـjitter.
  • Hierarchy: organizes devices hierarchically by their distance from the reference clock (stratum).
  • Synchronization: synchronizes devices via timestamped messages between peers.
  • Algorithms: uses complex algorithms to calculate network delay and jitter.

PTP (Precision Time Protocol): دقة زمنية أعلى من NTP، تُستخدم في العمليات الصناعية، شبكات 5G، الأجهزة الطبية، الخدمات المالية، والبث.

PTP (Precision Time Protocol): higher time precision than NTP, used in industrial processes, 5G networks, medical devices, financial services, and broadcasting.

  • Grandmaster clock: المصدر الزمني الرئيسي بمجال PTP.
  • Boundary clock وOrdinary clock: أنواع ساعات أخرى بالتسلسل الهرمي.
  • الأدوار: TimeTransmitter, TimeReceiver, Grandmaster, Boundary.
  • Grandmaster clock: the primary time source within a PTP domain.
  • Boundary clock and Ordinary clock: other clock types in the hierarchy.
  • Roles: TimeTransmitter, TimeReceiver, Grandmaster, Boundary.

Web, File, and Database Services

HTTP/HTTPS · FTP/SFTP · SMB · NAS · RDBMS vs NoSQL

HTTP: بروتوكول لجلب الموارد (مستندات HTML، صور، فيديوهات) من الويب — أساس أي تبادل بيانات على الويب.

HTTP: a protocol for fetching resources (HTML documents, images, videos) from the web — the foundation of any data exchange on the web.

FTP (File Transfer Protocol):

FTP (File Transfer Protocol):

  • Authentication: يطلب بيانات دخول، وبعض السيرفرات تسمح بوصول مجهول (anonymous).
  • Channels: قناة أوامر (command) للتعليمات والردود، وقناة بيانات (data) لنقل الملفات.
  • Transfer Modes: Active (السيرفر يتصل بالعميل لنقل البيانات) وPassive (العميل يبدأ اتصالات الأوامر/البيانات لتجنب مشاكل الجدار الناري).
  • Authentication: requires credentials, though some servers allow anonymous access.
  • Channels: a command channel for instructions and responses, and a data channel for transferring files.
  • Transfer Modes: Active (the server connects to the client for data transfer) and Passive (the client initiates the command/data connections to avoid firewall issues).

SMB (Server Message Block)

يسمح للأجهزة على نفس الشبكة بمشاركة الموارد. يُستخدم في Windows، وفي Linux عبر Samba.

Lets devices on the same network share resources. Used in Windows, and on Linux via Samba.

NAS (Network Attached Storage)

يوفّر وصولًا عن بُعد للملفات ووصولًا متزامنًا لعدة أجهزة. مكوناته: معالج، ذاكرة، أقراص صلبة، ونظام تشغيل مخصص (غالبًا لينكس).

Provides remote file access and simultaneous access for multiple devices. Its components: a processor, memory, hard drives, and a dedicated OS (usually Linux).

Email and Voice Services

SMTP · IMAP · VoIP · SIP

SMTP (Simple Mail Transfer Protocol): يُستخدم لإرسال البريد من سيرفر لآخر، يوجّه الرسائل من عميل المرسل لسيرفر بريد المستقبل. يمكن دمجه مع TLS لتشفير البريد أثناء النقل.

SMTP (Simple Mail Transfer Protocol): used to send mail from one server to another, routing messages from the sender's client to the recipient's mail server. Can be combined with TLS to encrypt mail in transit.

المنافذ: Port 25 (عادي) · Port 465 (implicit TLS) · Port 587 (explicit TLS).

Ports: Port 25 (plain) · Port 465 (implicit TLS) · Port 587 (explicit TLS).

IMAP (Internet Message Access Protocol): يتيح الوصول لإدارة البريد عن بُعد، ويخزّن الرسائل على السيرفر. وظائفه: الاتصال بسيرفر البريد، المزامنة، قراءة الرسائل، وإدارتها.

IMAP (Internet Message Access Protocol): enables remote mail management access, and stores messages on the server. Its functions: connecting to the mail server, syncing, reading messages, and managing them.

Disaster Recovery and High Availability

Disaster Recovery and High Availability

مفاهيم التعافي من الكوارث:

Disaster Recovery Concepts:

  • BRP (Disaster Recovery Plan): إرشادات وإجراءات، تحضير ومنع.
  • Tabletop Exercises: محاكاة (simulation) وتعلّم بنّاء (constructive learning).
  • Validation Tests: اختبار وظيفي (functional)، اختبار سيناريو (scenario)، اختبار كامل النطاق (full-scale).
  • BCP (Business Continuity Plan): فريق BCP، تحليل أثر الأعمال (BIA)، وخطة التواصل بالأزمات.
  • DRP (Disaster Recovery Plan): guidelines and procedures, preparation and prevention.
  • Tabletop Exercises: simulation and constructive learning.
  • Validation Tests: functional testing, scenario testing, full-scale testing.
  • BCP (Business Continuity Plan): a BCP team, a Business Impact Analysis (BIA), and a crisis communication plan.

مواقع التعافي من الكوارث (Disaster Recovery Sites): Cold Site (بنية أساسية بدون معدات جاهزة، الأبطأ والأرخص) · Warm Site (معدات جزئية جاهزة) · Hot Site (نسخة كاملة جاهزة للعمل فورًا، الأسرع والأغلى).

Disaster Recovery Sites: a Cold Site (basic infrastructure with no equipment ready, the slowest and cheapest) · a Warm Site (partial equipment ready) · a Hot Site (a full copy ready to operate immediately, the fastest and most expensive).

Fault Tolerance

يحافظ على استمرار العمل رغم فشل مكوّن، يعمل بسعة مخفّضة بدل التوقف الكامل، عبر التكرار (replication)، فحص الأخطاء، والـfailover.

Keeps operations running despite a component failure, running at reduced capacity instead of shutting down completely, via replication, error checking, and failover.

Redundancy

يكرر المكونات الأساسية لموثوقية أعلى، يوفّر مسارات/سعة احتياطية، ويمنع انهيار النظام من فشل نقطة واحدة.

Duplicates core components for higher reliability, provides backup paths/capacity, and prevents system collapse from a single point of failure.

Load Balancer يوزّع طلبات العملاء عبر عدة سيرفرات (Round Robin / Least Connections) لمنع إرهاق سيرفر واحد.
A Load Balancer distributes client requests across several servers (Round Robin / Least Connections) to prevent overloading a single server.

Load Balancers: توزّع ترافيك الشبكة عبر عدة سيرفرات (كـ"شرطي مرور")، تضمن عدم إرهاق سيرفر واحد، تقلل التوقف وتزيد قابلية التوسع. أنواعها: hardware-based أو software-based، وتستخدم خوارزميات مثل Round Robin وLeast Connections.

Load Balancers: distribute network traffic across several servers (like a "traffic cop"), ensuring no single server is overloaded, reducing downtime and increasing scalability. Types: hardware-based or software-based, using algorithms like Round Robin and Least Connections.

High Availability Clusters: أنظمة تضمن تشغيلًا مستمرًا وتقلل التوقف عبر مكونات مكرَّرة وآليات failover — مثالية حيث الاستمرارية حرجة (قواعد البيانات، خدمات الأعمال).

High Availability Clusters: systems that ensure continuous operation and reduce downtime through duplicated components and failover mechanisms — ideal where continuity is critical (databases, business services).

First Hop Redundancy: يضمن استمرار خدمة الشبكة عبر التبديل التلقائي لبوابة احتياطية إذا فشلت الأساسية — بروتوكولات مثل HSRP وVRRP توفّر failover سريع وتمنع single point of failure عند البوابة.
First Hop Redundancy: ensures network service continues by automatically switching to a backup gateway if the primary one fails — protocols like HSRP and VRRP provide fast failover and prevent a single point of failure at the gateway.
