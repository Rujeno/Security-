المصادقة — Authentication

Authentication

Applying Network Security Features — AAA · Authentication Factors · SSO · Kerberos

مفاهيم AAA (تشبيه بطاقة صعود الطائرة):

AAA concepts (boarding-pass analogy):

  • Identity: حساب أو معرّف يمثّل مستخدمًا/جهازًا/عملية بشكل فريد على الشبكة — من يدّعي أنه هو.
  • Authentication: عامل/عوامل تثبت أن الشخص هو من يدّعي — إثبات الهوية.
  • Authorization: الحقوق والصلاحيات الممنوحة داخل النظام — أين مسموح له الذهاب وأي مستوى وصول.
  • Accounting: تتبّع الاستخدام المصرّح/غير المصرّح به للمورد — تسجيل النشاط.
  • Identity: an account or identifier that uniquely represents a user/device/process on the network — who they claim to be.
  • Authentication: the factor(s) that prove the person is who they claim to be — proving identity.
  • Authorization: the rights and permissions granted within the system — where they're allowed to go and what access level.
  • Accounting: tracking authorized/unauthorized use of a resource — logging activity.
أولًا تُحدَّد الهوية (من أنت)، ثم تُثبَت (Authentication)، ثم تُمنح الصلاحيات (Authorization)، وأخيرًا يُسجَّل كل نشاط (Accounting).
First identity is established (who you are), then it's authenticated, then authorization is granted, and finally every activity is logged (accounting).

Single Sign-On (SSO): تسجيل دخول واحد يمنح وصولًا لعدة تطبيقات/خدمات (مثل حساب Microsoft الواحد للوصول لـTeams, Outlook, OneDrive, SharePoint) بدون تكرار تسجيل الدخول لكل خدمة.

Single Sign-On (SSO): one login that grants access to multiple applications/services (e.g. a single Microsoft account for Teams, Outlook, OneDrive, SharePoint) without re-logging in for each service.

Kerberos: بروتوكول مصادقة SSO يستخدم نظام tickets (عبر Ticket Granting Service) للتحقق من هوية المستخدم مرة واحدة، ثم استخدام التذاكر للوصول للخدمات المختلفة بدون إعادة إدخال بيانات الدخول.

Kerberos: an SSO authentication protocol that uses a ticket system (via a Ticket Granting Service) to verify the user's identity once, then uses tickets to access different services without re-entering credentials.

التفويض وإدارة الحسابات

Authorization and Account Management

Authorization and Account Management — Access Control Models · PAM

DAC (Discretionary Access Control)

DAC (Discretionary Access Control)

وصول يتحكم به مالك المورد نفسه — هو من يقرر من يصل لملفاته/موارده.

Access controlled by the owner of the resource itself — they decide who can reach their files/resources.

RBAC (Role-Based Access Control)

RBAC (Role-Based Access Control)

الوصول يُمنح حسب الدور الوظيفي للمستخدم داخل المؤسسة، لا بشكل فردي.

Access is granted based on the user's job role within the organization, not individually.

مصطلحات إدارة الوصول:

Access management terms:

  • Privileged Account: حساب للتغييرات الجوهرية بالنظام.
  • PAM (Privileged Access Management): ضوابط لمنع إساءة استخدام الحسابات المميّزة.
  • Least Privilege: منح المستخدمين الصلاحيات الكافية فقط لأداء عملهم، لا أكثر.
  • Separation of Duties: تقسيم المهام الحساسة بين عدة أشخاص لمنع سوء الاستخدام.
  • Privileged Account: an account for making fundamental changes to the system.
  • PAM (Privileged Access Management): controls to prevent misuse of privileged accounts.
  • Least Privilege: granting users only the permissions sufficient for their job, no more.
  • Separation of Duties: splitting sensitive tasks among several people to prevent misuse.
مثال تطبيقي: مدير الأنظمة يحتاج وصولًا لإعدادات السيرفرات والأمان، بينما مندوب المبيعات يحتاج فقط لبرنامج المبيعات وقاعدة بيانات العملاء — هذا هو مبدأ Least Privilege عمليًا.
Practical example: a systems admin needs access to server and security settings, while a sales rep only needs the sales program and customer database — that's Least Privilege in practice.

Defense in Depth: البيانات (الأصل الأهم) في المركز، محاطة بطبقات حماية متتالية — كل طبقة تُبطئ أو توقف مهاجمًا تجاوز الطبقة التي قبلها.
Defense in Depth: data (the most important asset) sits at the center, surrounded by successive protective layers — each layer slows or stops an attacker who got past the layer before it.
كل مضيف وجهاز شبكة يجب تحصينه — تحديث النظام، إغلاق المنافذ/الخدمات غير الضرورية، تغيير بيانات الدخول الافتراضية، وتطبيق سياسات كلمات مرور قوية.
Every host and network device must be hardened — update the system, close unnecessary ports/services, change default credentials, and enforce strong password policies.

أمان السويتش — Switch Security

Switch Security

NAC · Port Security

مصطلحات أساسية: NAC (Network Access Control): نظام لمصادقة وتفويض الوصول للشبكة. Switch: يربط ويدير الاتصال على الشبكة. Switch Ports: منافذ مخصصة على السويتش لتوصيل الأجهزة.

Basic terms: NAC (Network Access Control): a system for authenticating and authorizing access to the network. Switch: connects and manages communication on the network. Switch Ports: dedicated ports on the switch for connecting devices.

إجراءات أمان المنافذ (Port Security):

Port Security measures:

  • تأمين الوصول الفيزيائي للسويتش.
  • تحديث الـfirmware بانتظام.
  • تعطيل المنافذ غير المستخدَمة.
  • إعداد MAC filtering لتحديد الأجهزة المسموح لها.
  • تفعيل Router Advertisement (RA) Guard.
  • إعداد DHCP snooping لفحص أصالة ترافيك DHCP.
  • تطبيق مصادقة 802.1x (EAP).
  • Secure physical access to the switch.
  • Update firmware regularly.
  • Disable unused ports.
  • Configure MAC filtering to define allowed devices.
  • Enable Router Advertisement (RA) Guard.
  • Configure DHCP snooping to inspect the authenticity of DHCP traffic.
  • Apply 802.1x (EAP) authentication.
سيناريو: جهاز غير مصرّح به اتصل بغرفة السيرفرات → أمّني الوصول الفيزيائي (خزائن قابلة للقفل) → عطّلي المنافذ غير المستخدَمة → فعّلي MAC filtering → فعّلي DHCP snooping لفحص أصالة ترافيك DHCP.
Scenario: an unauthorized device connected in the server room → secure physical access (lockable cabinets) → disable unused ports → enable MAC filtering → enable DHCP snooping to check the authenticity of DHCP traffic.

أخطاء إعداد الجدار الناري الشائعة:

Common firewall configuration mistakes:

  • ACL متساهلة جدًا (Overly permissive).
  • ACL متشددة جدًا (Overly prohibitive).
  • عدم تطبيق implicit deny (الرفض الافتراضي لما لم يُسمح صراحة).
  • إعدادات تسجيل (logging) غير صحيحة.
  • Overly permissive ACL.
  • Overly prohibitive ACL.
  • Not applying implicit deny (denying by default anything not explicitly allowed).
  • Incorrect logging settings.
ملخص الوحدة 10: التحكم بالوصول يضمن وصول المستخدمين/الأجهزة المصرّح لهم فقط؛ الدفاع متعدد الطبقات يحمي السرية والسلامة والتوفر؛ الجدران النارية والـProxy servers ترشّح الترافيك وتدير الطلبات؛ تصفية المحتوى تضبط الترافيك بدقة حسب البروتوكول والعناوين والمحتوى.
Module 10 summary: access control ensures only authorized users/devices connect; defense in depth protects confidentiality, integrity, and availability; firewalls and proxy servers filter traffic and manage requests; content filtering fine-tunes traffic by protocol, addresses, and content.
