بروتوكولات Transport وApplication

Implementing Network Services — TCP · UDP

دور طبقة Transport (L4): توصيل بيانات التطبيقات multiplexed فوق الاتصال الأساسي والعنونة والتوجيه اللي توفّرها الطبقات 1-3.

TCP (Transmission Control Protocol): ينقل البيانات بطريقة موثوقة (reliable) بين الأجهزة. للحفاظ على حالة الاتصال، يحتاج حقول رأس (header fields) كثيرة:

Source port, Destination port, Sequence number, Ack number, Data length, Flags, Window, Checksum, Urgent Pointer, Options

TCP Three-Way Handshake:

SYN←SYN + ACK←ACK←Connection Established

UDP (User Datagram Protocol): ينقل البيانات بطريقة غير مضمونة (non-guaranteed) بدون handshake أو تتبع حالة — أخف وأسرع لكن بدون ضمان وصول. حقول الرأس أبسط: Source port, Destination port, Message length, Checksum.

فرّقي: TCP = اتصال موثوق مع handshake وتتبع حالة (مثل الويب والبريد). UDP = إرسال سريع بدون ضمان (مثل البث الحي والـVoIP).
MODULE 6 · LESSON 6.2

DHCP — التوزيع التلقائي لعناوين IP

DHCP Process · Server Configuration · Reservations & Exclusions

عملية DHCP (DORA):

DHCP Discover (Client)←DHCP Offer (Server)←DHCP Request (Client)←DHCP Ack (Server)

إعداد سيرفر DHCP: يجب أن يُعطى عنوان IP ثابت (static)، ويُهيَّأ بنطاق (scope) من عناوين IP/subnet masks لتوزيعها.

DHCP Reservations

تضمن حصول جهاز معيّن دائمًا على نفس عنوان IP، مرتبطة بعنوان MAC الجهاز — مثالية للأجهزة اللي تحتاج عنوان IP ثابت (طابعات، سيرفرات).

DHCP Exclusions

تمنع توزيع نطاق معيّن من عناوين IP — يُحجز ولا يُوزَّع، مثالية للعناوين المخصصة يدويًا (statically assigned) لأجهزة أخرى.

APIPA وSLAAC

Automatic Private IP Addressing · IPv6 Autoconfiguration

APIPA (Automatic Private IP Addressing): يسمح للأجهزة بتعيين عنوان IP لنفسها ذاتيًا عندما لا يتوفر سيرفر DHCP — للاستخدام على الشبكة المحلية فقط.

  • يعيّن لنفسه عنوانًا بين 169.254.0.1 و169.254.254.255.
  • يستخدم ARP للتأكد أن العنوان فريد وغير مكرر.

IPv6 Autoconfiguration: يسمح لأجهزة شبكة IPv6 بضبط عناوينها الخاصة بدون الحاجة لـDHCP. نوعان:

  • SLAAC — Stateless Address Autoconfiguration
  • DHCPv6 — Stateful Address Autoconfiguration

DHCP Relay واستكشاف الأخطاء

DHCP Relay Agent · IP Helper

DHCP Relay Agent: يعمل كجسر شبكي — يستقبل رسائل DHCP broadcast من العملاء ويمررها لسيرفر DHCP، ما يمكّن العملاء من الحصول على عنوان IP من سيرفر DHCP بعيد (على subnet مختلفة).

IP Helper: ميزة على أجهزة شبكة Cisco تمرر ترافيك DHCP وبث آخر بين subnets مختلفة.

  • يترجم البث (broadcast) إلى unicast لعبور حدود الـsubnet.
  • يرسل طلبات DHCP من العملاء لسيرفر في subnet مختلفة.
MODULE 6 · LESSON 6.5

نظام أسماء النطاقات — DNS

DNS Hierarchy · Resource Records · DNS Security

Host Names

معرّفات محلية، يعيّنها المسؤول، أسماء سهلة الفهم للبشر، فريدة على الشبكة المحلية فقط.

Domain Names

معرّفات عالمية، بنية هرمية، تتجنب التكرار على الإنترنت، ومُسجَّلة عبر registrar.

هرمية DNS (DNS Hierarchy): Root DNS Servers → Top Level Domain (.com, .org, .gov...) → Domain (مثل comptia.org) → Sub-Domain (مثل help.comptia.org).

أنواع السجلات (Resource Records)

السجلالوظيفة
SOAيحدد جهة السلطة (authority) لمنطقة DNS، يحتوي معلومات التواصل الإداري ومعدلات التحديث والإصدار
Host Address (A)يربط اسم النطاق بعنوان IPv4، ضروري لترجمة الأسماء إلى IP

Service (SRV)يحدد مواقع خدمات معيّنة داخل نطاق، يشمل رقم المنفذ وأولوية الخدمة
Text (TXT)يخزّن معلومات نصية لمصادر خارجية، تُستخدم لسجلات SPF وDKIM لتقليل السبام
Pointer (PTR)يُستخدم لعمليات البحث العكسي (reverse DNS lookup)، يربط عنوان IP باسم النطاق

أنواع سيرفرات DNS:

  • Primary DNS Servers: تترجم أسماء النطاقات لعناوين IP، وتكون أول نقطة اتصال لاستعلامات DNS.
  • Secondary DNS Servers: توفّر تكرارًا وموازنة حِمل، وتعمل كنسخة احتياطية عند فشل السيرفر الأساسي.
  • Cache-only DNS Servers: تخزّن نتائج الحل (caching) لتسريع الاستجابة، وتقلل الحمل على السيرفرات الأساسية/الثانوية.

Internal DNS: يحل أسماء النطاقات الداخلية، تديره فرق IT للشبكة المحلية، يعزز الأمان بعزل الترافيك. External DNS: يحل أسماء نطاقات الإنترنت للمستخدمين، تديره جهات خارجية، يركّز على حل النطاقات العامة.

استكشاف أخطاء DNS

DNS Troubleshooting

أعراض مشاكل DNS: انتهاء المهلة وأخطاء (timeouts/errors)، فشل جزئي بحل الأسماء، مشاكل تحميل الصفحات، تأخّر الوصول للمواقع.

طرق حل الأسماء (Name Resolution Methods):

  • تحقق من local name cache على الجهاز.
  • تحقق من ملف HOSTS.
  • تحقق من سجلات DNS باستخدام nslookup (ويندوز) أو dig (لينكس).
