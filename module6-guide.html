بروتوكولات Transport وApplication

Transport and Application Protocols

Implementing Network Services — TCP · UDP

دور طبقة Transport (L4): توصيل بيانات التطبيقات multiplexed فوق الاتصال الأساسي والعنونة والتوجيه اللي توفّرها الطبقات 1-3.

The role of the Transport layer (L4): delivering multiplexed application data on top of the basic connectivity, addressing, and routing provided by layers 1-3.

TCP (Transmission Control Protocol): ينقل البيانات بطريقة موثوقة (reliable) بين الأجهزة. للحفاظ على حالة الاتصال، يحتاج حقول رأس (header fields) كثيرة:

TCP (Transmission Control Protocol): transfers data reliably between devices. To maintain connection state, it needs many header fields:

Source port, Destination port, Sequence number, Ack number, Data length, Flags, Window, Checksum, Urgent Pointer, Options

TCP Three-Way Handshake:

SYN←SYN + ACK←ACK←Connection Established

UDP (User Datagram Protocol): ينقل البيانات بطريقة غير مضمونة (non-guaranteed) بدون handshake أو تتبع حالة — أخف وأسرع لكن بدون ضمان وصول. حقول الرأس أبسط: Source port, Destination port, Message length, Checksum.

UDP (User Datagram Protocol): transfers data on a non-guaranteed basis with no handshake or state tracking — lighter and faster, but with no delivery guarantee. The header fields are simpler: Source port, Destination port, Message length, Checksum.

فرّقي: TCP = اتصال موثوق مع handshake وتتبع حالة (مثل الويب والبريد). UDP = إرسال سريع بدون ضمان (مثل البث الحي والـVoIP).
Tell them apart: TCP = a reliable connection with a handshake and state tracking (like the web and email). UDP = fast transmission with no guarantee (like live streaming and VoIP).

DHCP — التوزيع التلقائي لعناوين IP

DHCP — Automatic IP Address Distribution

DHCP Process · Server Configuration · Reservations & Exclusions

عملية DHCP (DORA)The DHCP Process (DORA):

DHCP Discover (Client)←DHCP Offer (Server)←DHCP Request (Client)←DHCP Ack (Server)
تسلسل DORA: العميل يبث Discover، السيرفر يعرض Offer، العميل يطلب Request، السيرفر يؤكد بـACK.
The DORA sequence: the client broadcasts Discover, the server responds with Offer, the client sends Request, and the server confirms with ACK.

إعداد سيرفر DHCP: يجب أن يُعطى عنوان IP ثابت (static)، ويُهيَّأ بنطاق (scope) من عناوين IP/subnet masks لتوزيعها.

DHCP server configuration: it must be given a static IP address, and configured with a scope of IP addresses/subnet masks to distribute.

DHCP Reservations

تضمن حصول جهاز معيّن دائمًا على نفس عنوان IP، مرتبطة بعنوان MAC الجهاز — مثالية للأجهزة اللي تحتاج عنوان IP ثابت (طابعات، سيرفرات).

Ensures a specific device always gets the same IP address, tied to the device's MAC address — ideal for devices that need a fixed IP (printers, servers).

DHCP Exclusions

تمنع توزيع نطاق معيّن من عناوين IP — يُحجز ولا يُوزَّع، مثالية للعناوين المخصصة يدويًا (statically assigned) لأجهزة أخرى.

Prevents a specific range of IP addresses from being distributed — reserved but never handed out, ideal for addresses statically assigned to other devices.

APIPA وSLAACand SLAAC

Automatic Private IP Addressing · IPv6 Autoconfiguration

APIPA (Automatic Private IP Addressing): يسمح للأجهزة بتعيين عنوان IP لنفسها ذاتيًا عندما لا يتوفر سيرفر DHCP — للاستخدام على الشبكة المحلية فقط.

APIPA (Automatic Private IP Addressing): lets devices assign themselves an IP address when no DHCP server is available — for local network use only.

  • يعيّن لنفسه عنوانًا بين 169.254.0.1 و169.254.254.255.
  • يستخدم ARP للتأكد أن العنوان فريد وغير مكرر.
  • Assigns itself an address between 169.254.0.1 and 169.254.254.255.
  • Uses ARP to confirm the address is unique and not duplicated.

IPv6 Autoconfiguration: يسمح لأجهزة شبكة IPv6 بضبط عناوينها الخاصة بدون الحاجة لـDHCP. نوعان:

IPv6 Autoconfiguration: lets IPv6 network devices configure their own addresses without needing DHCP. Two types:

  • SLAAC — Stateless Address Autoconfiguration
  • DHCPv6 — Stateful Address Autoconfiguration

DHCP Relay واستكشاف الأخطاء

DHCP Relay and Troubleshooting

DHCP Relay Agent · IP Helper

DHCP Relay Agent: يعمل كجسر شبكي — يستقبل رسائل DHCP broadcast من العملاء ويمررها لسيرفر DHCP، ما يمكّن العملاء من الحصول على عنوان IP من سيرفر DHCP بعيد (على subnet مختلفة).

DHCP Relay Agent: acts as a network bridge — it receives DHCP broadcast messages from clients and forwards them to a DHCP server, letting clients obtain an IP address from a remote DHCP server (on a different subnet).

IP Helper: ميزة على أجهزة شبكة Cisco تمرر ترافيك DHCP وبث آخر بين subnets مختلفة.

IP Helper: a feature on Cisco network devices that forwards DHCP and other broadcast traffic between different subnets.

  • يترجم البث (broadcast) إلى unicast لعبور حدود الـsubnet.
  • يرسل طلبات DHCP من العملاء لسيرفر في subnet مختلفة.
  • Translates broadcast traffic into unicast to cross subnet boundaries.
  • Sends clients' DHCP requests to a server on a different subnet.

نظام أسماء النطاقات — DNS

Domain Name System — DNS

DNS Hierarchy · Resource Records · DNS Security

Host Names

معرّفات محلية، يعيّنها المسؤول، أسماء سهلة الفهم للبشر، فريدة على الشبكة المحلية فقط.

Local identifiers, assigned by the admin, human-friendly names, unique only on the local network.

Domain Names

معرّفات عالمية، بنية هرمية، تتجنب التكرار على الإنترنت، ومُسجَّلة عبر registrar.

Global identifiers, hierarchical structure, avoid duplication across the internet, registered through a registrar.

هرمية DNS (DNS Hierarchy): Root DNS Servers → Top Level Domain (.com, .org, .gov...) → Domain (مثل comptia.org) → Sub-Domain (مثل help.comptia.org).

The DNS Hierarchy: Root DNS Servers → Top Level Domain (.com, .org, .gov...) → Domain (e.g. comptia.org) → Sub-Domain (e.g. help.comptia.org).

من الأعلى للأسفل: Root → Top Level Domain → Domain → Sub-Domain — كل مستوى يحل جزءًا من الاسم الكامل.
Top to bottom: Root → Top Level Domain → Domain → Sub-Domain — each level resolves part of the full name.

أنواع سيرفرات DNS:

Types of DNS Servers:

  • Primary DNS Servers: تترجم أسماء النطاقات لعناوين IP، وتكون أول نقطة اتصال لاستعلامات DNS.
  • Secondary DNS Servers: توفّر تكرارًا وموازنة حِمل، وتعمل كنسخة احتياطية عند فشل السيرفر الأساسي.
  • Cache-only DNS Servers: تخزّن نتائج الحل (caching) لتسريع الاستجابة، وتقلل الحمل على السيرفرات الأساسية/الثانوية.
  • Primary DNS Servers: translate domain names to IP addresses, and are the first point of contact for DNS queries.
  • Secondary DNS Servers: provide redundancy and load balancing, and act as a backup if the primary server fails.
  • Cache-only DNS Servers: cache resolution results to speed up responses, and reduce load on primary/secondary servers.

Internal DNS: يحل أسماء النطاقات الداخلية، تديره فرق IT للشبكة المحلية، يعزز الأمان بعزل الترافيك. External DNS: يحل أسماء نطاقات الإنترنت للمستخدمين، تديره جهات خارجية، يركّز على حل النطاقات العامة.

Internal DNS: resolves internal domain names, managed by IT teams for the local network, boosts security by isolating traffic. External DNS: resolves internet domain names for users, managed by external parties, focused on resolving public domains.

استكشاف أخطاء DNS

DNS Troubleshooting

DNS Troubleshooting

أعراض مشاكل DNS: انتهاء المهلة وأخطاء (timeouts/errors)، فشل جزئي بحل الأسماء، مشاكل تحميل الصفحات، تأخّر الوصول للمواقع.

Symptoms of DNS problems: timeouts/errors, partial name resolution failures, page loading problems, delayed site access.

طرق حل الأسماء (Name Resolution Methods):

Name Resolution Methods:

  • تحقق من local name cache على الجهاز.
  • تحقق من ملف HOSTS.
  • تحقق من سجلات DNS باستخدام nslookup (ويندوز) أو dig (لينكس).
  • Check the local name cache on the device.
  • Check the HOSTS file.
  • Check DNS records using nslookup (Windows) or dig (Linux).
ملخص الوحدة 6: TCP نقل موثوق مع تأكيد استلام؛ DHCP يوزّع IP وsubnet mask وبارامترات اختيارية (gateway/DNS) تلقائيًا؛ Relay Agents تمرّر ترافيك DHCP بين الـsubnets؛ DNS ترجمة هرمية عالمية من أسماء النطاقات لعناوين IP.
Module 6 summary: TCP is a reliable transport with delivery acknowledgment; DHCP automatically distributes IP, subnet mask, and optional parameters (gateway/DNS); Relay Agents forward DHCP traffic between subnets; DNS is a global hierarchical translation from domain names to IP addresses.
