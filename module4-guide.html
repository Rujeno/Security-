أساسيات بروتوكول الإنترنت — Internet Protocol Basics

Internet Protocol Basics

Configuring Network Addressing — ARP وأنواع العنونة

Configuring Network Addressing — ARP and Addressing Types

ARP (Address Resolution Protocol): يعمل مثل دليل هاتف — يربط عنوان IP بعنوان MAC المقابل له على الشبكة المحلية، ليتمكن الجهاز من توجيه الإطار للوجهة الصحيحة.

ARP (Address Resolution Protocol): works like a phone book — it maps an IP address to its corresponding MAC address on the local network, so the device can forward the frame to the correct destination.

عنونة IPv4 — IPv4 Addressing

IPv4 Addressing

تركيب العنوان · Network/Host ID · Subnet Mask · Default Gateway

Address format · Network/Host ID · Subnet Mask · Default Gateway

تركيب عنوان IPv4: تمثيل عشري لأربع مجموعات ثنائية (octets)، كل octet 8 bits → المجموع 32 bit.

IPv4 address format: a decimal representation of four binary groups (octets), each octet 8 bits → a total of 32 bits.

مثال تحويل ثنائي: 11000011 → بالأوزان 128-64-32-16-8-4-2-1: البتات المفعّلة 64+32+1 = 97

Binary conversion example: 11000011 → using weights 128-64-32-16-8-4-2-1: the set bits give 64+32+1 = 97

تشبيه العمارة السكنية:

The apartment building analogy:

  • Network ID = رقم المبنى (مشترك بين كل السكان/المضيفين).
  • Host ID = رقم الشقة (يحدد مضيفًا بعينه داخل الشبكة).
  • Default Gateway = المدخل الرئيسي للمبنى — طريق الخروج للخارج (خارج الشبكة المحلية).
  • Broadcast Address = مثل مكبّر صوت يصل لكل السكان.
  • Network ID = the building number (shared by all residents/hosts).
  • Host ID = the apartment number (identifies a specific host within the network).
  • Default Gateway = the building's main entrance — the way out to the outside (beyond the local network).
  • Broadcast Address = like a loudspeaker that reaches every resident.

Subnet Mask: يحدد الجزء الخاص بالشبكة من عنوان IP. إذا طابق network ID الشبكةَ المحلية تُرسل الحزمة مباشرة، وإلا تُمرَّر (forwarded) لشبكة أخرى.

Subnet Mask: identifies the network portion of an IP address. If the network ID matches the local network, the packet is sent directly; otherwise it's forwarded to another network.

مثال: شبكة 192.168.1.x بقناع 255.255.255.0 → أول 3 octets (24 bit) للشبكة، والoctet الأخير للمضيف.

Example: network 192.168.1.x with mask 255.255.255.0 → the first 3 octets (24 bits) are the network, and the last octet is the host.

مثال /24 — 255.255.255.0: أول 3 octets = عنوان الشبكة (لا يتغيّر بين المضيفين)، والoctet الأخير = عنوان المضيف الفريد.
Example /24 — 255.255.255.0: the first 3 octets = the network address (unchanged between hosts), and the last octet = the unique host address.

قواعد تصميم مخطط عنونة IPv4:

Rules for designing an IPv4 addressing scheme:

  • عدد الشبكات/الشبكات الفرعية المطلوبة، وعدد المضيفين بكل subnet.
  • الـNetwork ID يجب أن يكون من مدى خاص صالح.
  • لا يجوز أن يكون Network ID أو Host ID كله بتات 1 (فهذا عنوان broadcast).
  • كل Host ID فريد داخل الـsubnet، وكل Network ID فريد على مستوى الشبكة.
  • The number of networks/subnets needed, and the number of hosts per subnet.
  • The Network ID must come from a valid private range.
  • The Network ID or Host ID cannot be all 1 bits (that's a broadcast address).
  • Every Host ID is unique within the subnet, and every Network ID is unique across the network.

Classless Addressing (استعارة البتات / Borrowing Bits): استعارة بتات من جزء الـHost لصالح جزء الـNetwork → يزيد عدد الشبكات الفرعية المتاحة لكن يقلل عدد المضيفين الممكنين بكل subnet.

Classless Addressing (Borrowing Bits): borrowing bits from the Host portion in favor of the Network portion → increases the number of available subnets but reduces the number of possible hosts per subnet.

مثال: الشبكة 192.168.89.0/24 (قناع 255.255.255.0) — باستعارة بت واحد فقط:

Example: the network 192.168.89.0/24 (mask 255.255.255.0) — borrowing just one bit:

  • الـNetwork ID الجديد: 192.168.89.128
  • مدى العناوين: 192.168.89.1 – 192.168.89.126
  • القناع الجديد: 255.255.255.128 أو /25
  • The new Network ID: 192.168.89.128
  • Address range: 192.168.89.1 – 192.168.89.126
  • The new mask: 255.255.255.128 or /25

وباستعارة بتين: Network ID = 192.168.89.192، المدى 192.168.89.1–.62، القناع 255.255.255.192 (/26).

And borrowing two bits: Network ID = 192.168.89.192, range 192.168.89.1–.62, mask 255.255.255.192 (/26).

بتات مُستعارة لصالح الشبكة (Network)   بتات المضيف (Host) — الـ8 خانات تمثّل الـoctet الأخير من 192.168.89.0
Bits borrowed for the Network   Host bits — the 8 positions represent the last octet of 192.168.89.0

CIDR — Classless Inter-Domain Routing

يخصص مساحة عناوين IP بكفاءة أكبر، عبر دمج العنوان مع لاحقة (suffix) تمثّل جزء الشبكة، ويدعم variable-length subnetting.

Allocates IP address space more efficiently by combining the address with a suffix representing the network portion, and supports variable-length subnetting.

VLSM — Variable Length Subnetting

ينشئ subnets بأحجام مختلفة داخل نفس الشبكة لتخصيص أكفأ لعناوين IP، لكنه يتطلب تخطيطًا وإدارة دقيقة.

Creates subnets of different sizes within the same network for more efficient IP address allocation, but requires careful planning and management.

استكشاف أخطاء IP — IP Troubleshooting

IP Troubleshooting

IP Configuration Issues · Duplicate IP/MAC · IP Forwarding Issues

استكشاف أخطاء إعداد IP يحدث بطبقة Network. إذا استبعدتِ مشكلة بطبقتي Physical وData Link، الخطوة التالية فحص العنونة والإعداد الأساسي. إذا تعذّر على المضيف اكتشاف الجيران (neighbor discovery)، استخدمي أولًا ipconfig (ويندوز) أو ip/ifconfig (لينكس) للتحقق من إعداد المضيف.

IP configuration troubleshooting happens at the Network layer. Once you've ruled out a Physical and Data Link layer problem, the next step is checking addressing and basic configuration. If a host fails at neighbor discovery, first use ipconfig (Windows) or ip/ifconfig (Linux) to verify the host's configuration.

عنوان IP خاطئ (Incorrect IP Address): كل مضيف يجب أن يملك نفس قناع الشبكة (netmask) مثل جيرانه، وعنوان مضيف صالح وفريد ضمن الـsubnet.

Incorrect IP Address: every host must have the same netmask as its neighbors, and a valid, unique host address within the subnet.

مثال: الشبكة 192.168.1.0/24 — Host A: 192.168.1.10، Host B: 192.168.1.11 (كلاهما صحيح) — لكن Host C: 192.168.0.21 بنفس القناع 255.255.255.0 يقع فعليًا بـsubnet مختلفة (192.168.0.0 وليس 192.168.1.0). ستحاول Host A وB الوصول لـHost C عبر الـdefault gateway، وHost C على الأغلب لن تتمكن من التواصل بالشبكة إطلاقًا.

Example: network 192.168.1.0/24 — Host A: 192.168.1.10, Host B: 192.168.1.11 (both correct) — but Host C: 192.168.0.21 with the same mask 255.255.255.0 actually sits on a different subnet (192.168.0.0, not 192.168.1.0). Host A and B will try to reach Host C through the default gateway, and Host C will likely fail to communicate on the network at all.

مع أقنعة غير افتراضية (مثل /28) يصعب تحديد نطاق المضيفين الصالح بالنظر السريع — لازم تحويل العناوين لثنائي للتأكد. تذكّري: لا عنوان الشبكة (network address) ولا عنوان البث (broadcast address) يصلحان كعنوان مضيف.

With non-default masks (like /28) it's hard to determine the valid host range at a glance — you need to convert the addresses to binary to be sure. Remember: neither the network address nor the broadcast address is valid as a host address.

قناع شبكة خاطئ (Incorrect Subnet Mask) — سيناريوهان:

Incorrect Subnet Mask — two scenarios:

  • قناع أطول من اللازم: المضيف يظن أنه يحتاج توجيه (route) عبر الـdefault gateway للتواصل مع مضيفين هم فعليًا بنفس الشبكة المحلية — يُحمّل الراوتر بترافيك غير ضروري.
  • قناع أقصر من اللازم: المضيف يظن أن مضيفًا بعيدًا هو بنفس شبكته المحلية بينما هو فعليًا بشبكة أخرى — يفشل بالتواصل لأنه لا يستخدم الـgateway وهو محتاجه. قد يرسل الراوتر رسائل ICMP redirect للمضيف بهذي الحالة.
  • A mask longer than needed: the host thinks it needs to route through the default gateway to reach hosts that are actually on the same local network — loading the router with unnecessary traffic.
  • A mask shorter than needed: the host thinks a remote host is on its own local network when it's actually on another network — communication fails because it doesn't use the gateway when it needs to. The router may send the host ICMP redirect messages in this case.

تكرار عناوين IP وMAC (Duplicate IP/MAC Address Issues):

Duplicate IP/MAC Address Issues:

  • Duplicate IP: قد ينتج عن خطأ بالإعداد اليدوي أو تعارض بنطاق DHCP. Windows يكتشف التكرار ويعطّل العنوان مع تحذير. Linux عادة لا يعطّل الواجهة لكنه قد يسجّل تحذيرًا بالسجلات — يحدث "race condition" يحدد أي مضيف يستقبل الترافيك. للتشخيص: ping ثم arp -a لفحص عناوين MAC، وعلى لينكس أداة arping -D للإبلاغ عن ردود مكرَّرة.
  • Duplicate MAC: يسبب مشكلة مشابهة — يتنافس الجهازان على الرد على استعلامات ARP، وينقسم التواصل بينهما أو يصل لواحد فقط. نادر الحدوث إلا مع عنونة مُدارة محليًا (locally administered addressing). ⚠️ مشاكل عنونة MAC قد تكون مؤشرًا على هجوم spoofing.
  • تشخيص مشاكل MAC: أداة arp للتحقق من عناوين MAC المسجّلة لكل مضيف، ipconfig أو ip neigh لفحص عنوان MAC للواجهة، فحص جداول MAC/ARP على السويتشات والراوترات، واستخدام محلّل بروتوكول (protocol analyzer) لفحص ترافيك ARP وتحديد من يحاول انتحال نفس عنوان MAC.
  • Duplicate IP: can result from a manual configuration error or a DHCP scope conflict. Windows detects the duplicate and disables the address with a warning. Linux usually doesn't disable the interface but may log a warning — a "race condition" occurs that determines which host receives traffic. To diagnose: ping then arp -a to check MAC addresses, and on Linux the arping -D tool to report duplicate replies.
  • Duplicate MAC: causes a similar problem — both devices compete to answer ARP queries, and communication either splits between them or reaches only one. Rare except with locally administered addressing. ⚠️ MAC addressing problems can be a sign of a spoofing attack.
  • Diagnosing MAC problems: the arp tool to check the MAC address recorded for each host, ipconfig or ip neigh to check an interface's MAC address, checking MAC/ARP tables on switches and routers, and using a protocol analyzer to inspect ARP traffic and identify who is trying to spoof the same MAC address.

مشاكل توجيه IP (IP Forwarding Issues): إذا بدا إعداد عنوان المضيف المحلي صحيحًا، أكملي سلسلة اختبارات اتصال بـping لتحديد موقع ونطاق العطل المحتمل:

IP Forwarding Issues: if the local host's address configuration looks correct, complete a chain of ping connectivity tests to locate the scope of the likely fault:

Ping loopback←Ping host←Ping gateway←Ping remote host←Ping host name←Establish session
  1. Ping عنوان الـloopback (127.0.0.1): للتأكد أن TCP/IP مثبَّت ومحمَّل بشكل صحيح — إذا فشل، أعيدي تثبيت حزمة بروتوكول الشبكة.
  2. Ping عنوان IP المضيف المحلي: للتأكد أنه أُضيف بشكل صحيح وأن محول الشبكة (network adapter) يعمل — إذا فشل، فقد يكون خطأ إعداد أو عطل بالمحول/الـdriver.
  3. Ping عنوان IP الـdefault gateway: للتأكد أنه يعمل ويمكن التواصل مع مضيف آخر بالشبكة المحلية.
  4. Ping عناوين IP لمضيفين آخرين بنفس الـsubnet: لاختبار مشاكل الإعداد المحلي أو الرابط. إذا تعذّر الـping وكان الخطأ "destination unreachable"، تحققي من عدم وجود عنوان IP أو netmask خاطئ. إذا كانت صحيحة لكن الـping ما زال ينتهي بمهلة، اشتبهي بمشكلة أمنية (مثل إعداد أمان منفذ السويتش) أو مشكلة بطبقة Data Link أو Physical.
  5. Ping عنوان IP لمضيف بعيد: للتأكد من إمكانية التواصل عبر الراوتر. إذا تعذّر الوصول لعنوان بعيد، تحققي من إعداد الـdefault gateway بالمضيف المحلي لاستبعاد مشكلة gateway خاطئ. إذا كان الـgateway صحيحًا ويمكن عمل ping له، ابدئي التحقيق ببنية التوجيه (routing infrastructure).
  1. Ping the loopback address (127.0.0.1): to confirm TCP/IP is installed and loaded correctly — if it fails, reinstall the network protocol stack.
  2. Ping the local host's IP address: to confirm it was added correctly and the network adapter is working — if it fails, there may be a configuration error or an adapter/driver fault.
  3. Ping the default gateway's IP address: to confirm it's working and another host on the local network can be reached.
  4. Ping other hosts' IP addresses on the same subnet: to test for local configuration or link problems. If the ping fails with "destination unreachable," check for an incorrect IP address or netmask. If those are correct but the ping still times out, suspect a security issue (like switch port security configuration) or a Data Link/Physical layer problem.
  5. Ping a remote host's IP address: to confirm communication through the router is possible. If a remote address is unreachable, check the local host's default gateway configuration to rule out an incorrect gateway. If the gateway is correct and pingable, start investigating the routing infrastructure.
⚠️ انتبهي أن ICMP قد يكون محجوبًا بجدار ناري أو برنامج أمان، خصوصًا عند عمل ping لمضيفين بعيدين. هذا الأسلوب المنهجي مناسب عند عدم القدرة على تشخيص السبب أو عند التحقق من إعداد IP جديد/مُعدَّل — لكن عمليًا، قد تبدئين مباشرة بـping لمضيف بعيد لتحديد المشكلة أو إعادة إنتاجها بسرعة.
⚠️ Keep in mind that ICMP may be blocked by a firewall or security software, especially when pinging remote hosts. This systematic approach is useful when you can't diagnose the cause, or when verifying a new/modified IP configuration — but in practice you might start directly by pinging a remote host to identify or quickly reproduce the problem.
ملخص الوحدة 4: IP يربط شبكات متعددة بعناوين فريدة؛ IPv4 = 32 bit/4 octets؛ الـsubnet = segment على طبقة الشبكة (L3)؛ أدوات TCP/IP للفحص والإعداد؛ IPv6 = ثمانية مجموعات 16-bit بصيغة hex؛ استكشاف الأخطاء يبدأ بفحص الإعداد المحلي ثم تسلسل ping من loopback حتى مضيف بعيد.
Module 4 summary: IP connects multiple networks with unique addresses; IPv4 = 32 bits/4 octets; a subnet = a segment at the Network layer (L3); TCP/IP tools for inspection and configuration; IPv6 = eight 16-bit groups in hex; troubleshooting starts by checking the local configuration, then a ping sequence from loopback to a remote host.
