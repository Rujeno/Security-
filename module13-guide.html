الشبكات الواسعة والاتصال بالإنترنت

Comparing Remote Access Methods — WAN and Internet Connectivity

WAN مقابل LAN: الـWAN ينقل البيانات لمسافات كبيرة، غالبًا عبر شبكات عامة. الـLAN يغطي مناطق أصغر ومحلية. Enterprise WAN: شبكة لمؤسسة واحدة تمتد لمناطق جغرافية واسعة، تستخدم بنية اتصالات عامة.

WAN وطبقات OSI:

  • Physical Layer: يحدد الوسائط والواجهات، يستخدم مودمات لاتصالات الكيبل النحاسي (تناظرية ورقمية).
  • Data Link Layer: بروتوكولات أبسط من إيثرنت الـLAN، لكن الإيثرنت يُستخدم بشكل متزايد بالـWAN لكفاءة الاتصال الطرف-لطرف.
  • Network Layer: يستخدم IP للعنونة، يربط مواقع العميل والمزوّد عبر راوترات CE وPE، ويخصص عناوين IPv4/IPv6 عامة للتعريف العالمي.

أنواع اتصال الإنترنت

النوعالسرعةالخصائص

FTTC (Fiber to the Curb)

ألياف بصرية حتى الأرصفة القريبة من المباني، ثم كيبل نحاسي/coax للمرحلة الأخيرة — سرعة وموثوقية أعلى من النحاس التقليدي، لكن أقل قليلًا من FTTP.

FTTP (Fiber to the Premises)

ألياف بصرية حتى المبنى مباشرة — أعلى سرعة ممكنة، بنية مستقبلية قابلة للتوسع، لكن تكلفة تركيب أعلى وقد لا تتوفر بكل المناطق.

مقارنة طرق الوصول عن بُعد — VPN

Tunneling Protocols · IPSec · Client-to-Site & Site-to-Site VPN

سياسة الوصول عن بُعد: وصول مصرّح به فقط مع تحقق قوي من الهوية، استخدام VPNs وتشفير البيانات أثناء النقل، تأمين الأجهزة البعيدة (تحديثات، مضاد فيروسات)، وصول قائم على الدور، سجلات وصول مفصّلة، وتحديثات أمنية دورية لأجهزة RAS.

بروتوكولات النفق (Tunneling Protocols): تمرّر بيانات خاصة بأمان عبر شبكات عامة، عبر تغليف الحزم داخل حزم أخرى، لإنشاء أنفاق آمنة تضمن وصولًا حصريًا بين المرسل والمستقبل.

البروتوكولطبقة OSIالخصائص
PPPData Linkللخطوط الرقمية، يفتقر لأمان مدمج
GRENetworkتغليف بروتوكولات متعددة
IPSecNetworkتأمين IP عبر المصادقة والتشفير
TLS/DTLSSessionأمان بعبء إضافي أعلى، تُستخدم بـVPN للاتصال المشفّر والموثّق عن بُعد

أوضاع IPSec:

  • Transport Mode: يُستخدم غالبًا داخل شبكة خاصة، يشفّر الحمولة (payload) فقط. AH يوفّر سلامة رأس IP، وESP يشفّر الحمولة للسرية.
  • Tunnel Mode: مثالي لشبكات VPN وتأمين الاتصالات عبر شبكات عامة — يشفّر الحزمة كاملة بما فيها الرأس، ويُغلّفها داخل حزمة IP جديدة.

خطوات إعداد IPSec: اختيار Transport أو Tunnel حسب متطلبات الشبكة → تحديد AH و/أو ESP → إدارة مفاتيح تلقائية عبر IKE أو يدوية → تعريف سياسات التعامل مع الترافيك → اختبار الإعداد دوريًا.

IKE (Internet Key Exchange): بروتوكول IPSec للتواصل الآمن عبر الإنترنت، أساسي لبنية VPN موثوقة — يتفاوض وينشئ SAs، مصادقة متبادلة، وتبادل مفاتيح تشفير.

  • IKEv1: VPN موقع-لموقع ومضيف-لمضيف، قناة موثقة آمنة.
  • IKEv2: يدعم EAP للمصادقة، إعداد أبسط، اجتياز NAT أفضل، MOBIKE للاتصال المتنقل — المفضّل لحلول VPN الحديثة.

Client-to-Site VPN

عملاء أفراد يتصلون بشبكة الشركة عبر الإنترنت العام. المكونات: VPN Client (البرنامج/الجهاز المبادِر) وVPN Gateway (راوتر مفعَّل بـVPN عند حافة الشبكة) — مثالي للعمل عن بُعد.

Site-to-Site VPN

اتصال دائم بين شبكتين — أمان عالٍ، إدارة مبسّطة (بدون إعداد كل جهاز فرديًا)، وقابلية توسع. حالات استخدام: ربط الفروع، الدمج والاستحواذ، شبكات IIoT، والتكامل السحابي.

بروتوكولات VPN: SSL/TLS VPN (نفق آمن بشهادات، مثل SSTP) وL2TP/IPSec (أمان قوي منتشر). بروتوكول PPTP مُهجَّر (deprecated) لثغراته الأمنية.

Split Tunnel مقابل Full Tunnel: توازن بين الوصول المباشر للإنترنت والحاجة الأمنية — Split يمرر فقط ترافيك الشركة عبر النفق، Full يمرر كل الترافيك.

Clientless VPN: وصول لموارد الشبكة عبر المتصفح، بدون الحاجة لبرنامج VPN مخصص، باستخدام HTML5 وWebSockets — يبسّط الوصول، يعزل الجلسة داخل المتصفح، وفعّال من ناحية التكلفة. أمثلة: Microsoft RDS، Citrix، Apache Guacamole.

الإدارة عن بُعد — Remote Management

SSH · Telnet · RDP · Console/OOB · Jump Boxes

Remote Host Access: يتيح التحكم عن بُعد بالحواسيب وأجهزة الشبكة — إعداد الأجهزة، إدارة السيرفرات/المستخدمين، عبر واجهة رسومية (GUI) أو طرفية (terminal).

SSH (Secure Shell): بروتوكول اتصال آمن مشفّر بالكامل — للوصول عن بُعد للسيرفرات وأجهزة الشبكة، نقل ملفات آمن، جلسات طرفية، وتنفيذ أوامر.

الأمرالوظيفة
sshيتصل بسيرفر بعيد لبدء جلسة shell آمنة
ssh-keygenيولّد زوج مفاتيح SSH (خاص/عام)
ssh-copy-idينسخ مفتاحًا عامًا لملف authorized_keys على السيرفر البعيد
ssh-addيضيف مفاتيح خاصة لوكيل المصادقة

Telnet: محاكاة طرفية للوصول لنظام بعيد، يستمع افتراضيًا على المنفذ TCP 23. اتصالاته (بما فيها كلمات المرور) غير مشفرة — عرضة للتنصت وإعادة التشغيل. أفضل الممارسات: تجنّبيه للمهام الحساسة، عطّليه واحجبي المنفذ 23، واستخدمي SSH بدلًا منه.

RDP (Remote Desktop Protocol): بروتوكول مايكروسوفت للتحكم بسطح المكتب عن بُعد، منفذ TCP 3389، يدعم واجهة رسومية، مؤمّن بتشفير وNLA (Network Level Authentication). أفضل الممارسات: تجنّب استخدامه من أجهزة منخفضة الثقة، استخدام SAW للاتصالات الإدارية. بدائل: TeamViewer، VNC، Citrix.

Console Connections

اتصال مباشر لإعداد/استكشاف أخطاء أجهزة الشبكة، عبر كيبل console (rollover) متصل بجهاز به برنامج محاكي طرفية — لإعداد الأجهزة عند تعذّر الوصول عبر الشبكة.

OOB (Out-of-Band) Management

قناة مخصصة لإدارة الجهاز بمعزل عن ترافيك البيانات — وصول آمن وموثوق للوظائف الإدارية خصوصًا أثناء انقطاع الشبكة. أمثلة: منفذ AUX، منفذ إدارة IP منفصل.

Jump Box: نقطة وصول آمنة لإدارة سيرفرات/أجهزة داخل subnet محمي أو شبكة سحابية — تعمل كمدخل وحيد يقلل سطح الهجوم. يتصل المسؤولون بالـJump Box عبر SSH/RDP، ومنها فقط يمكن الوصول لواجهات الإدارة — سيرفرات التطبيقات مُعدَّة لقبول اتصالات من الـJump Box فقط.

API Connection Methods: أتمتة عبر سكريبتات بدل الإعداد اليدوي — ممارسات أمنية: مصادقة قوية، تجنّب حساب root للأتمتة، مفاتيح سرية للوصول البرمجي، HTTPS للتواصل، ومبدأ Least Privilege لحسابات الأتمتة.
