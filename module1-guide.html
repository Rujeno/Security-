مفهوم الشبكة وأنواعها

Networking Overview — Network Types and Characteristics

الشبكة (Network): مجموعة من الأجهزة (computers and devices) متصلة ببعضها عبر transmission medium (وسيط نقل: كيبل نحاسي، ألياف بصرية، أو لاسلكي)، هدفها مشاركة الموارد (shared resources) والتواصل وتبادل المعلومات — تمامًا مثل شبكتك الاجتماعية لكن في بيئة رقمية.

نموذجا التشغيل: Peer-to-Peer vs Client-Server

Peer-to-Peer (P2P)

كل جهاز يعمل كـ client وserver في نفس الوقت. لا يوجد جهاز مركزي. مناسبة للشبكات الصغيرة، لكن إدارتها وأمانها أصعب مع التوسع.

Client-Server

يوجد server مركزي يقدّم الخدمات والموارد (ملفات، طباعة، مصادقة) لأجهزة الـclients. هذا هو النموذج المعتمد في بيئات الشركات — مثل بيئتك في مدائن مع Google Workspace.

الشبكة المحلية LAN وأنواعها

Local Area Network (LAN): شبكة محصورة في موقع جغرافي واحد (single geographical location). أنواعها حسب الحجم:

  • SOHO (Small Office / Home Office): شبكة منزل أو مكتب صغير، غالبًا راوتر واحد متعدد الوظائف.
  • Enterprise LAN: شبكة شركة بمبنى أو حرم، فيها سيرفرات وسويتشات مُدارة.
  • Datacenter: شبكة مخصصة لربط السيرفرات وأنظمة التخزين بكثافة عالية.

هيكليات الشبكة — Network Topologies

الـTopology = مخطط الاتصالات بين أجهزة الشبكة (layout of connections)

1) Point-to-Point: عقدتان فقط (two nodes) متصلتان مباشرة بنفس الوسيط. مفاهيم مهمة هنا:

  • Half-duplex: الجهاز لا يستطيع الإرسال والاستقبال في نفس اللحظة (بالتناوب).
  • Full-duplex: إرسال واستقبال متزامن (simultaneously).

2) Star Topology: كل عقدة تتصل بجهاز مركزي يسمى concentrator عبر وسيط مخصص لها.

  • لو كان الـconcentrator يكرر الإشارة للجميع = يعمل كـEthernet hub (logical bus).
  • الأشيع: يتتبع عناوين الأجهزة ويوجّه الاتصال بشكل انتقائي = Switch (ينشئ point-to-point links).
  • العيب الأهم للاختبار: الـconcentrator هو single point of failure، وكل عقدة يجب أن تكون ضمن مسافة النقل القصوى للوسيط أو تستخدم repeater.

3) Mesh Topology:

  • Full mesh: كل عقدة متصلة بكل عقدة أخرى. عدد الروابط = n*(n−1)/2 — يكبر بسرعة مع إضافة العقد.
  • Partial mesh: الأكثر عملية؛ العقد تتعلم الـtopology وتمرر الحزم (forward packets).
  • الميزة: مسارات متعددة = مرونة عالية (resilience) عند فشل روابط أو عقد.
إذا شفتِ في السؤال "single point of failure" فكري بـStar، وإذا "redundant paths / resilience" فكري بـMesh، وإذا "two nodes only / duplex" فهي Point-to-Point.

نموذج OSI — الطبقات السبع

OSI Model Concepts — أهم موضوع تأسيسي في الشهادة كلها

نموذج مرجعي يقسّم عملية الاتصال الشبكي إلى 7 طبقات. عند المرسل (Sender) تنزل البيانات من الطبقة 7 إلى 1 (encapsulation)، وعند المستقبل (Receiver) تصعد من 1 إلى 7 (de-encapsulation).

الجملة التذكيرية (Mnemonic) من الطبقة 1 إلى 7: Please Do Not Throw Sausage Pizza Away

7
Application
تتفاعل مباشرة مع برامج المستخدم لطلب خدمة الشبكة. أمثلة: SMTP, DNS, FTP
6
Presentation
تجهيز شكل البيانات: Encryption/Decryption, Encoding, Compression, MIME
5
Session
إنشاء وإدارة الجلسات بين التطبيقات. أمثلة: NetBIOS, PAP, ASP, ADSP
4
Transport
تتبع الاتصال بين التطبيقات عبر الـports، تقسيم البيانات (segmentation) وإعادة تجميعها (reassembly). أجهزة: Multilayer switch, Advanced firewall, IDS
3
Network
نقل الحزم (packets) بين الشبكات باستخدام IP addresses. أجهزة: Router, ACL, Basic firewall
2
Data Link
نقل الـframes بين العقد على نفس الـsegment باستخدام MAC addresses. أجهزة: Switch, Bridge, NIC, Wireless AP
1
Physical
إرسال الـbits كإشارات عبر الوسيط. أمثلة: Cables, Hubs, Repeaters, Modem, Transceiver

تقسيم المسؤولية (يجي كثير بالاختبار):

  • الطبقات 1–3 (Physical, Data Link, Network) = Responsibility of the Network.
  • الطبقات 4–7 (Transport → Application) = Responsibility of the Host.
اربطي كل طبقة بوحدة بياناتها: L1 = Bits · L2 = Frames · L3 = Packets · L4 = Segments. واربطي الجهاز بالطبقة: Hub→1، Switch→2، Router→3.

SOHO Router — راوتر واحد بكل الطبقات

جهاز واحد يجمع وظائف عدة طبقات من OSI

الطبقةوظيفة الـSOHO Router فيها
Physical (L1)منافذ RJ-45 LAN ports لتوصيل الأجهزة سلكيًا، radio antennas للواي فاي، ومنفذ WAN port للاتصال بمزود الخدمة (ISP).
Data Link (L2)يعمل كـEthernet switch + Wireless Access Point (الـAP موصول داخليًا بمنفذ switch). كل جهاز يُعرَّف بـMAC address، والأجهزة السلكية واللاسلكية كلها على نفس layer 2 local network.
Network (L3)يوجّه بين الشبكة الخاصة المحلية والإنترنت العام، يشغّل DHCP server لتوزيع IP على الأجهزة، وواجهة الـWAN تأخذ public IP address.
Transport / Application (L4–L7)تقسيم البيانات (segmentation) وإعادة تجميعها، وتمرير طلبات واستجابات Application layer.

اتصال SOHO بالإنترنت: الـWAN يربط شبكتك بمزود الخدمة عبر بنية مثل PSTN (Public Switched Telephone Network)، والإنترنت نفسه يتكون من high-bandwidth trunks تربط نقاط تبادل الإنترنت IXPs (Internet Exchange Points) حيث تتصل شبكات مزودي الخدمة ببعض.

الأرقام الثنائية — Binary

أساس فهم IP addressing و Subnetting لاحقًا

النظام العشري (Base 10) خاناته: آحاد، عشرات، مئات... أما الثنائي (Binary / Base 2) فكل خانة من الـ8 bits لها وزن:

1286432168421
كل bit إما 1 (نجمع وزنه) أو 0 (نتجاهله)

مثال 1 — تحويل 205: نبدأ من الأكبر: 128 ✓ (باقي 77) → 64 ✓ (باقي 13) → 32 ✗ → 16 ✗ → 8 ✓ (باقي 5) → 4 ✓ (باقي 1) → 2 ✗ → 1 ✓
النتيجة: 205 = 1100 1101

مثال 2 — تحويل 132: 128 ✓ (باقي 4) → 4 ✓
النتيجة: 132 = 1000 0100

منهجية استكشاف الأخطاء — Troubleshooting Methodology

7 خطوات بالترتيب — احفظيها كتسلسل، الاختبار يسأل عن "الخطوة التالية"

1. Identify the problem← 2. Establish a theory of probable cause← 3. Test the theory← 4. Establish a plan of action← 5. Implement the solution← 6. Verify the solution← 7. Document findings, actions, and outcomes

الخطوة 1 — Identify the problem:

  • جمع المعلومات: system documentation, installation/maintenance logs, vendor support sites.
  • سؤال المستخدمين: open questions (لاكتشاف معلومات) وclosed questions (إجابة نعم/لا محددة).
  • تحديد الأعراض: فحص فعلي، سجلات (logs)، محاولة تكرار المشكلة (duplicate the problem).
  • هل تغيّر شيء؟ Did it ever work? What has changed since it was last working?
  • التعامل مع كل مشكلة على حدة (approach problems individually).

الخطوة 2 — Establish a theory: شكّكي في الأمور البديهية (question the obvious)، وأثبتي عمل كل مكوّن منهجيًا. باستخدام OSI:

  • Top-down: من Application نزولًا لـPhysical.
  • Bottom-up: من Physical صعودًا (الأشيع: تحقّقي من الكيبل أولًا!).
  • وأيضًا divide-and-conquer كاستراتيجية ثالثة.

الخطوة 3 — Test the theory: لا تقفزي للاستنتاجات. ومتى نصعّد (Escalation)؟

  • المشكلة تتجاوز معرفتك أو صلاحيتك.
  • الجهاز تحت system warranty.
  • نطاق المشكلة كبير جدًا، أو العميل صعب/مسيء.

الخطوات 5–7: نفّذي الحل (وصعّدي إذا احتجتِ صلاحية أعلى)، تحققي أن النظام يعمل لك وللمستخدم، ثم وثّقي — السجلات مفيدة لأي مشكلة مستقبلية.
