مفهوم الشبكة وأنواعها

Network Concepts and Types

Networking Overview — Network Types and Characteristics

الشبكة (Network): مجموعة من الأجهزة (computers and devices) متصلة ببعضها عبر transmission medium (وسيط نقل: كيبل نحاسي، ألياف بصرية، أو لاسلكي)، هدفها مشاركة الموارد (shared resources) والتواصل وتبادل المعلومات — تمامًا مثل شبكتك الاجتماعية لكن في بيئة رقمية.

Network: a group of computers and devices connected to each other over a transmission medium (copper cable, fiber optic, or wireless), with the goal of sharing resources and exchanging information — much like your social network, but in a digital environment.

نموذجا التشغيل: Peer-to-Peer vs Client-Server

Operating Models: Peer-to-Peer vs Client-Server

Peer-to-Peer (P2P)

كل جهاز يعمل كـ client وserver في نفس الوقت. لا يوجد جهاز مركزي. مناسبة للشبكات الصغيرة، لكن إدارتها وأمانها أصعب مع التوسع.

Every device acts as both a client and a server at the same time. There is no central device. Suitable for small networks, but management and security become harder as it grows.

Client-Server

يوجد server مركزي يقدّم الخدمات والموارد (ملفات، طباعة، مصادقة) لأجهزة الـclients. هذا هو النموذج المعتمد في بيئات الشركات — مثل بيئتك في مدائن مع Google Workspace.

A central server provides services and resources (files, printing, authentication) to client devices. This is the model used in enterprise environments — such as a workplace running Google Workspace.

الشبكة المحلية LAN وأنواعها

Local Area Networks (LAN) and Their Types

Local Area Network (LAN): شبكة محصورة في موقع جغرافي واحد (single geographical location). أنواعها حسب الحجم:

Local Area Network (LAN): a network confined to a single geographical location. Its types by size:

  • SOHO (Small Office / Home Office): شبكة منزل أو مكتب صغير، غالبًا راوتر واحد متعدد الوظائف.
  • Enterprise LAN: شبكة شركة بمبنى أو حرم، فيها سيرفرات وسويتشات مُدارة.
  • Datacenter: شبكة مخصصة لربط السيرفرات وأنظمة التخزين بكثافة عالية.
  • SOHO (Small Office / Home Office): a home or small office network, usually a single multi-function router.
  • Enterprise LAN: a company network across a building or campus, with managed servers and switches.
  • Datacenter: a network dedicated to connecting servers and storage systems at high density.

1) Point-to-Point: عقدتان فقط (two nodes) متصلتان مباشرة بنفس الوسيط. مفاهيم مهمة هنا:

1) Point-to-Point: just two nodes connected directly over the same medium. Important concepts here:

  • Half-duplex: الجهاز لا يستطيع الإرسال والاستقبال في نفس اللحظة (بالتناوب).
  • Full-duplex: إرسال واستقبال متزامن (simultaneously).
  • Half-duplex: the device cannot send and receive at the same instant (it alternates).
  • Full-duplex: sending and receiving happen simultaneously.

2) Star Topology — الشكل الأشهر بالشبكات الحديثة.

2) Star Topology — the most common shape in modern networks.

كل جهاز (عقدة) يتصل بجهاز مركزي وحيد بدل ما يتصل مباشرة بباقي الأجهزة. اسم هذا الجهاز المركزي بشكل عام هو concentrator — يعني ببساطة "الجهاز اللي تتجمع عنده كل اتصالات الشبكة".

Every device (node) connects to a single central device instead of connecting directly to every other device. The generic name for this central device is a concentrator — simply put, "the device where all network connections converge."

دور الجهاز المركزي

The Role of the Central Device

إذا كان الجهاز المركزي Hub: الـHub "غبي" — ما يعرف مين المقصود بالبيانات، فلما يستقبل رسالة من جهاز، يكررها ويرسلها لكل الأجهزة المتصلة به.

If the central device is a Hub: a Hub is "dumb" — it doesn't know who the data is meant for, so when it receives a message from one device, it repeats it and sends it to every device connected to it.

مثال: جهاز 1 يريد إرسال بيانات لجهاز 3 → الـHub يرسل البيانات لأجهزة 2 و3 و4 كلهم، لكن جهاز 3 فقط هو اللي يقبلها (الباقي يتجاهلونها).

Example: Device 1 wants to send data to Device 3 → the Hub sends the data to Devices 2, 3, and 4 all at once, but only Device 3 accepts it (the rest discard it).

لهذا يقال إن الشبكة تعمل منطقيًا مثل Bus Topology — رغم أن شكلها الخارجي نجمي، لأن جميع الأجهزة تشترك في البيانات نفسها.

That's why the network is said to behave logically like a Bus Topology — even though it physically looks like a star, because every device shares the same data.

إذا كان الجهاز المركزي Switch: الـSwitch أذكى؛ يتعلم عناوين الأجهزة، وتحديدًا MAC Address، ثم يرسل البيانات إلى الجهاز المطلوب فقط.

If the central device is a Switch: a Switch is smarter; it learns device addresses, specifically each MAC Address, then sends the data only to the intended device.

مثال: جهاز 1 يريد التواصل مع جهاز 3 → الـSwitch يرسل البيانات مباشرة إلى جهاز 3، ولا يرسلها لبقية الأجهزة.

Example: Device 1 wants to communicate with Device 3 → the Switch sends the data directly to Device 3, and does not send it to the other devices.

لذلك كل جهاز لديه اتصال مستقل مع الـSwitch يسمى Point-to-Point Link — أي اتصال من نقطة إلى نقطة.

So every device has an independent connection to the Switch called a Point-to-Point Link — a connection from one point to another.

أهم عيب: Single Point of Failure — الجهاز المركزي هو نقطة فشل واحدة لكل الشبكة.

The biggest drawback: Single Point of Failure — the central device is a single point of failure for the whole network.

  • إذا تعطل كابل جهاز واحد → يتوقف ذلك الجهاز فقط.
  • إذا تعطل الـSwitch أو الـHub نفسه → تتوقف الشبكة كاملة.
  • If a single device's cable fails → only that device goes down.
  • If the Switch or Hub itself fails → the entire network goes down.

شرط المسافة: لكل نوع كابل مسافة قصوى ينقل البيانات خلالها بكفاءة، لذلك يجب أن يكون كل جهاز قريبًا بما يكفي من الجهاز المركزي. إذا كانت المسافة أطول من الحد المسموح، يمكن استخدام Repeater — جهاز يستقبل الإشارة الضعيفة ويعيد تقويتها وإرسالها.

The distance requirement: every cable type has a maximum distance over which it can carry data efficiently, so every device must be close enough to the central device. If the distance is longer than allowed, a Repeater can be used — a device that receives a weakened signal and re-amplifies it before sending it on.

أسهل طريقة تحفظينها: الـHub ينادي على الجميع، أما الـSwitch فيعرف عنوان الجهاز المطلوب ويرسل له مباشرة. وسؤال شائع بالاختبار: "ما نقطة الضعف الأساسية في Star Topology؟" ← تعطل الجهاز المركزي يؤدي إلى توقف الشبكة كلها.
The easiest way to remember it: a Hub shouts to everyone, while a Switch knows the intended device's address and sends straight to it. A common exam question: "What is the main weakness of a Star Topology?" ← the central device failing brings down the entire network.

3) Mesh Topology — بنية شبكة تكون فيها الأجهزة (العقد) مترابطة بأكثر من مسار، بدل الاعتماد على جهاز مركزي واحد فقط.

3) Mesh Topology — a network structure where devices (nodes) are interconnected through more than one path, instead of relying on a single central device.

الفكرة الأساسية: إذا تعطل رابط أو جهاز، تستطيع البيانات غالبًا الوصول من طريق آخر.

The core idea: if a link or device fails, the data can usually still get through via another path.

Full Mesh — الشبكة المتشابكة بالكامل— The Fully Interconnected Network

كل عقدة متصلة مباشرة بكل العقد الأخرى. مثال بـ4 أجهزة: A متصلة بـB وC وD، وB متصلة بـA وC وD، وهكذا — أي أن كل جهاز لديه رابط مباشر مع جميع الأجهزة.

Every node is connected directly to every other node. Example with 4 devices: A connects to B, C, and D; B connects to A, C, and D; and so on — meaning every device has a direct link to every other device.

حساب عدد الروابط = n(n−1)/2 حيث n عدد العقد:

Calculating the number of links = n(n−1)/2 where n is the number of nodes:

  • 4 عقد → 4×3/2 = 6 روابط.
  • 10 عقد → 10×9/2 = 45 رابطًا — يكبر العدد بسرعة شديدة مع إضافة أجهزة جديدة.
  • نقسم على 2 لأن الرابط بين A وB هو نفسه الرابط بين B وA، فلا نحسبه مرتين.
  • 4 nodes → 4×3/2 = 6 links.
  • 10 nodes → 10×9/2 = 45 links — the count grows very fast as devices are added.
  • We divide by 2 because the link between A and B is the same link as B and A, so it isn't counted twice.

Partial Mesh — الشبكة المتشابكة جزئيًا— The Partially Interconnected Network

لا تكون كل عقدة متصلة بجميع العقد الأخرى؛ بعض العقد المهمة لديها عدة اتصالات، بينما العقد الأقل أهمية قد يكون لديها اتصال واحد أو اتصالان فقط.

Not every node is connected to every other node; some important nodes have several connections, while less critical nodes may have only one or two.

مثال: للوصول من A إلى D يوجد أكثر من طريق — إما A→B→D أو A→C→D. إذا تعطل رابط A–B، يمكن استخدام المسار الآخر عبر C.

Example: to reach D from A there's more than one route — either A→B→D or A→C→D. If the A–B link fails, the other path through C can be used.

ماذا يعنيWhat does Forward Packets mean?؟

في شبكات الـMesh، قد لا تكون العقدة الوجهة النهائية للحزمة، لكنها تستقبلها ثم تمررها للعقدة التالية. مثال: A يريد إرسال بيانات إلى D عبر المسار A→B→C→D، فـB يمررها لـC، وC يمررها لـD — هذا يسمى Packet Forwarding.

In Mesh networks, a node may not be the packet's final destination, but it receives it and passes it on to the next node. Example: A wants to send data to D via the path A→B→C→D, so B forwards it to C, and C forwards it to D — this is called Packet Forwarding.

في الشبكات المعتمدة على أجهزة التوجيه، تتعلم العقد المسارات المتاحة عبر بروتوكولات مثل OSPF, IS-IS, BGP، ثم تختار المسار الأنسب حسب التكلفة أو السرعة أو عدد القفزات.

In router-based networks, nodes learn the available paths through protocols such as OSPF, IS-IS, BGP, then pick the best path based on cost, speed, or hop count.

أهم ميزة:The key advantage: Resilience

قدرة الشبكة على الاستمرار بالعمل عند حدوث عطل — لأن شبكة Mesh فيها مسارات متعددة، فإذا تعطل كابل أو رابط أو راوتر أو عقدة معينة، يمكن توجيه البيانات عبر مسار بديل (مثال: المسار الأساسي A→B→D يتعطل عند B، فتُستخدم A→C→D بدلًا عنه). لذلك تُعتبر Mesh أكثر اعتمادية من Star Topology التي قد تعتمد على جهاز مركزي واحد.

The network's ability to keep working when a failure occurs — because a Mesh network has multiple paths, so if a cable, link, router, or particular node fails, data can be routed over an alternate path (example: the primary path A→B→D fails at B, so A→C→D is used instead). That's why Mesh is considered more reliable than a Star Topology, which may depend on a single central device.

عيوب Mesh: تحتاج عددًا كبيرًا من الكابلات والمنافذ، تكلفتها مرتفعة، تركيبها وصيانتها أكثر تعقيدًا، وإدارة المسارات تصبح أصعب مع زيادة عدد العقد — لذلك Full Mesh غير عملية غالبًا بالشبكات الكبيرة، ويُستخدم Partial Mesh أكثر لأنه يحقق توازنًا بين الاعتمادية والتكلفة.

Drawbacks of Mesh: it needs a large number of cables and ports, its cost is high, installation and maintenance are more complex, and managing paths gets harder as the number of nodes grows — that's why Full Mesh is often impractical in large networks, and Partial Mesh is used more often because it strikes a balance between reliability and cost.

The OSI Model — The Seven Layers

OSI Model Concepts — أهم موضوع تأسيسي في الشهادة كلها

OSI Model Concepts — the single most foundational topic in the entire certification

نموذج مرجعي يقسّم عملية الاتصال الشبكي إلى 7 طبقات. عند المرسل (Sender) تنزل البيانات من الطبقة 7 إلى 1 (encapsulation)، وعند المستقبل (Receiver) تصعد من 1 إلى 7 (de-encapsulation).

A reference model that splits the network communication process into 7 layers. At the Sender, data travels down from Layer 7 to Layer 1 (encapsulation), and at the Receiver, it travels back up from 1 to 7 (de-encapsulation).

Converting 205 to Binary

منهجية استكشاف الأخطاء — Troubleshooting Methodology

Troubleshooting Methodology

7 خطوات بالترتيب — احفظيها كتسلسل، الاختبار يسأل عن "الخطوة التالية"

7 steps in order — memorize them as a sequence, the exam asks about "the next step"

1. Identify the problem← 2. Establish a theory of probable cause← 3. Test the theory← 4. Establish a plan of action← 5. Implement the solution← 6. Verify the solution← 7. Document findings, actions, and outcomes

الخطوة 1 — Identify the problem:

Step 1 — Identify the problem:

  • جمع المعلومات: system documentation, installation/maintenance logs, vendor support sites.
  • سؤال المستخدمين: open questions (لاكتشاف معلومات) وclosed questions (إجابة نعم/لا محددة).
  • تحديد الأعراض: فحص فعلي، سجلات (logs)، محاولة تكرار المشكلة (duplicate the problem).
  • هل تغيّر شيء؟ Did it ever work? What has changed since it was last working?
  • التعامل مع كل مشكلة على حدة (approach problems individually).
  • Gather information: system documentation, installation/maintenance logs, vendor support sites.
  • Question users: open questions (to uncover information) and closed questions (a specific yes/no answer).
  • Identify the symptoms: physical inspection, logs, attempt to duplicate the problem.
  • Did anything change? Did it ever work? What has changed since it was last working?
  • Approach problems individually.

الخطوة 2 — Establish a theory: شكّكي في الأمور البديهية (question the obvious)، وأثبتي عمل كل مكوّن منهجيًا. باستخدام OSI:

Step 2 — Establish a theory: question the obvious, and verify each component's operation systematically. Using OSI:

  • Top-down: من Application نزولًا لـPhysical.
  • Bottom-up: من Physical صعودًا (الأشيع: تحقّقي من الكيبل أولًا!).
  • وأيضًا divide-and-conquer كاستراتيجية ثالثة.
  • Top-down: starting at Application and working down to Physical.
  • Bottom-up: starting at Physical and working up (most common: check the cable first!).
  • And also divide-and-conquer as a third strategy.

الخطوة 3 — Test the theory: لا تقفزي للاستنتاجات. ومتى نصعّد (Escalation)؟

Step 3 — Test the theory: don't jump to conclusions. And when do we escalate?

  • المشكلة تتجاوز معرفتك أو صلاحيتك.
  • الجهاز تحت system warranty.
  • نطاق المشكلة كبير جدًا، أو العميل صعب/مسيء.
  • The problem is beyond your knowledge or authority.
  • The device is under system warranty.
  • The problem's scope is too large, or the customer is difficult/abusive.

الخطوات 5–7: نفّذي الحل (وصعّدي إذا احتجتِ صلاحية أعلى)، تحققي أن النظام يعمل لك وللمستخدم، ثم وثّقي — السجلات مفيدة لأي مشكلة مستقبلية.

Steps 5–7: implement the solution (escalating if you need higher privileges), verify the system works for you and the user, then document — logs are useful for any future problem.

UTP — Unshielded Twisted Pair

  • من 2 إلى 1800 زوج داخل غلاف بلاستيكي.

  • أزواج نحاسية مجدولة + تدريع موصل (conductive shielding).
  • حماية من EMI وتقليل crosstalk.
  • الاستخدام: المناطق عالية التداخل (مصانع، آلات) ونقل البيانات الحساسة.
  • فئات: Cat5e, 6, 7 — ويحتاج تعامل حذر عند التركيب.

تنفيذ التمديدات — Structured Cabling

Wiring Implementation

Structured Cabling System: طريقة قياسية لتمديد الشبكات في المباني المكتبية، عناصرها:

  • Work Area: نقطة اتصال المستخدم.
  • Horizontal Cabling: التمديد الأفقي على مستوى الطابق (يربط الـwork areas بغرفة الاتصالات).
  • Telecommunications Room / Closet (IDF): غرفة/خزانة المعدات لكل طابق.
  • Backbone Cabling: التمديد الرأسي الذي يربط الطوابق وغرف المعدات.
  • Entrance Facilities / Demarc: نقطة دخول خدمة المزوّد وحدّ المسؤولية بينك وبين شركة الاتصالات (LEC).

معايير الإنهاء T568A / T568B: ترتيبان قياسيان لتوصيل الأزواج الأربعة (8 pins) في موصل RJ-45. الفرق بينهما تبديل مواقع الزوجين الأخضر والبرتقالي. المهم: استخدمي نفس المعيار على الطرفين للكيبل المستقيم (straight-through).

Patch Panels: لوحات تسهّل إدارة الكيابل — من الخلف punch down blocks (IDC terminals) لإنهاء الكيابل بشكل آمن ومضغوط، ومن الأمام منافذ RJ45 تتيح إعادة تشكيل التوصيلات بسهولة. تدعم T568A وT568B.

خطوات التركيب: Preparation (أدوات + مسار) → Pulling cable (ترقيم/تمرير/تحزيم) → Termination (اتركي service loop، قصّي ورقّمي) → Connection (patch panel + work area) → Testing → Documentation.

استكشاف أخطاء الكيابل

Cable Troubleshooting — أهم درس عملي في الوحدة

مصطلحات القياس:

  • Speed (baud rate): عدد الرموز المرسلة في الـPhysical layer (Hz)، بينما bit rate / bandwidth بالـbps في Data Link.
  • Throughput: متوسط معدل النقل الفعلي عبر الزمن — يتأثر بالترميز والأخطاء والمسافة والتداخل.
  • Goodput: الإنتاجية على مستوى الـApplication layer بعد حساب فقد الحزم (packet loss).
  • Latency: زمن وصول الحزمة، يُقاس بـmilliseconds (ms).
  • Distance limitations: نوع الوسيط يحدد المسافة؛ الأداء يتأثر بالتوهين (attenuation, dB loss) والتداخل (SNR).

أعراض مشاكل الكيابل: بطء الإنترنت، انقطاعات عشوائية، connection timeouts، بطء التطبيقات، تقطيع الصوت/الفيديو، وعدم استقرار الرابط.

خطوات الفحص: فحص فيزيائي → التحقق من الـpatch cords واستبدالها بأخرى سليمة معروفة (known good) → اختبار الـtransceivers بأداة loopback → تجربة منفذ switch أو جهاز بديل → فحص التمديدات المهيكلة بالأدوات → التحقق من الـdrivers والـnetwork adapter.

Attenuation (التوهين): فقدان قوة الإشارة (يُقاس بـdB).

أسبابه: طول الكيبل، رفع الـimpedance، سلك رفيع، عوامل بيئية.
الحلول: تقصير المسافات، repeaters/extenders، كيابل أعلى جودة، وقياس التوهين عند التركيب.

Interference (التداخل): تأثير سلبي من إشارات EMI / RFI وcrosstalk وموصلات معيبة.

الحلول: التدريع (foil/braided shields)، تنظيم مسارات الكيابل، مواد متينة وstrain relief، واختبار التوافق.

أنواع الـCrosstalk (تداخل الإشارات بين الأزواج):

  • NEXT (Near End Crosstalk): عند طرف المرسل — سببه فك الجدل الزائد أو درع معيب.
  • ACRN (Attenuation to Crosstalk Ratio, Near end): مقارنة insertion loss مع NEXT — قيمة عالية = إشارة قوية.
  • ACRF (…, Far End): قياس FEXT عند طرف المستقبل — مستقل عن طول الرابط.
  • Power Sum: لكيابل Gigabit / 10GbE — يتأكد أن الكيبل مناسب للإرسال على كل الأزواج معًا.
  • Alien Crosstalk: تداخل من كيابل مجاورة بسبب التحزيم الضيق أو الإنهاء السيئ.

حلول الـcrosstalk: فحص التلف والتركيب الخاطئ، تجنّب فك الجدل الزائد (excessive untwisting)، تحزيم صحيح، وموصلات/كيابل مناسبة.

فرّقي: مشكلة عند نهاية المرسل = NEXT · عند المستقبل = ACRF/FEXT · من كيابل مجاورة = Alien Crosstalk · فقدان قوة الإشارة مع المسافة = Attenuation.

عنونة IPv4 — IPv4 Addressing

تركيب العنوان · Network/Host ID · Subnet Mask · Default Gateway

تركيب عنوان IPv4: تمثيل عشري لأربع مجموعات ثنائية (octets)، كل octet 8 bits → المجموع 32 bit.

مثال تحويل ثنائي: 11000011 → بالأوزان 128-64-32-16-8-4-2-1: البتات المفعّلة 64+32+1 = 97

تشبيه العمارة السكنية:

  • Network ID = رقم المبنى (مشترك بين كل السكان/المضيفين).
  • Host ID = رقم الشقة (يحدد مضيفًا بعينه داخل الشبكة).
  • Default Gateway = المدخل الرئيسي للمبنى — طريق الخروج للخارج (خارج الشبكة المحلية).
  • Broadcast Address = مثل مكبّر صوت يصل لكل السكان.

Subnet Mask: يحدد الجزء الخاص بالشبكة من عنوان IP. إذا طابق network ID الشبكةَ المحلية تُرسل الحزمة مباشرة، وإلا تُمرَّر (forwarded) لشبكة أخرى.

مثال: شبكة 192.168.1.x بقناع 255.255.255.0 → أول 3 octets (24 bit) للشبكة، والoctet الأخير للمضيف.

مثال /24 — 255.255.255.0: أول 3 octets = عنوان الشبكة (لا يتغيّر بين المضيفين)، والoctet الأخير = عنوان المضيف الفريد.

  • مدى العناوين: 192.168.89.1 – 192.168.89.126
  • القناع الجديد: 255.255.255.128 أو /25

استكشاف أخطاء IP — IP Troubleshooting

IP Configuration Issues · Duplicate IP/MAC · IP Forwarding Issues

استكشاف أخطاء إعداد IP يحدث بطبقة Network. إذا استبعدتِ مشكلة بطبقتي Physical وData Link، الخطوة التالية فحص العنونة والإعداد الأساسي. إذا تعذّر على المضيف اكتشاف الجيران (neighbor discovery)، استخدمي أولًا ipconfig (ويندوز) أو ip/ifconfig (لينكس) للتحقق من إعداد المضيف.

عنوان IP خاطئ (Incorrect IP Address): كل مضيف يجب أن يملك نفس قناع الشبكة (netmask) مثل جيرانه، وعنوان مضيف صالح وفريد ضمن الـsubnet.

مثال: الشبكة 192.168.1.0/24 — Host A: 192.168.1.10، Host B: 192.168.1.11 (كلاهما صحيح) — لكن Host C: 192.168.0.21 بنفس القناع 255.255.255.0 يقع فعليًا بـsubnet مختلفة (192.168.0.0 وليس 192.168.1.0). ستحاول Host A وB الوصول لـHost C عبر الـdefault gateway، وHost C على الأغلب لن تتمكن من التواصل بالشبكة إطلاقًا.

مع أقنعة غير افتراضية (مثل /28) يصعب تحديد نطاق المضيفين الصالح بالنظر السريع — لازم تحويل العناوين لثنائي للتأكد. تذكّري: لا عنوان الشبكة (network address) ولا عنوان البث (broadcast address) يصلحان كعنوان مضيف.

قناع شبكة خاطئ (Incorrect Subnet Mask) — سيناريوهان:

  • قناع أطول من اللازم: المضيف يظن أنه يحتاج توجيه (route) عبر الـdefault gateway للتواصل مع مضيفين هم فعليًا بنفس الشبكة المحلية — يُحمّل الراوتر بترافيك غير ضروري.
  • قناع أقصر من اللازم: المضيف يظن أن مضيفًا بعيدًا هو بنفس شبكته المحلية بينما هو فعليًا بشبكة أخرى — يفشل بالتواصل لأنه لا يستخدم الـgateway وهو محتاجه. قد يرسل الراوتر رسائل ICMP redirect للمضيف بهذي الحالة.

تكرار عناوين IP وMAC (Duplicate IP/MAC Address Issues):

  • Duplicate IP: قد ينتج عن خطأ بالإعداد اليدوي أو تعارض بنطاق DHCP. Windows يكتشف التكرار ويعطّل العنوان مع تحذير. Linux عادة لا يعطّل الواجهة لكنه قد يسجّل تحذيرًا بالسجلات — يحدث "race condition" يحدد أي مضيف يستقبل الترافيك. للتشخيص: ping ثم arp -a لفحص عناوين MAC، وعلى لينكس أداة arping -D للإبلاغ عن ردود مكرَّرة.
  • Duplicate MAC: يسبب مشكلة مشابهة — يتنافس الجهازان على الرد على استعلامات ARP، وينقسم التواصل بينهما أو يصل لواحد فقط. نادر الحدوث إلا مع عنونة مُدارة محليًا (locally administered addressing). ⚠️ مشاكل عنونة MAC قد تكون مؤشرًا على هجوم spoofing.
  • تشخيص مشاكل MAC: أداة arp للتحقق من عناوين MAC المسجّلة لكل مضيف، ipconfig أو ip neigh لفحص عنوان MAC للواجهة، فحص جداول MAC/ARP على السويتشات والراوترات، واستخدام محلّل بروتوكول (protocol analyzer) لفحص ترافيك ARP وتحديد من يحاول انتحال نفس عنوان MAC.

مشاكل توجيه IP (IP Forwarding Issues): إذا بدا إعداد عنوان المضيف المحلي صحيحًا، أكملي سلسلة اختبارات اتصال بـping لتحديد موقع ونطاق العطل المحتمل:

Ping loopback←Ping host←Ping gateway←Ping remote host←Ping host name←Establish session
  1. Ping عنوان الـloopback (127.0.0.1): للتأكد أن TCP/IP مثبَّت ومحمَّل بشكل صحيح — إذا فشل، أعيدي تثبيت حزمة بروتوكول الشبكة.
  2. Ping عنوان IP المضيف المحلي: للتأكد أنه أُضيف بشكل صحيح وأن محول الشبكة (network adapter) يعمل — إذا فشل، فقد يكون خطأ إعداد أو عطل بالمحول/الـdriver.
  3. Ping عنوان IP الـdefault gateway: للتأكد أنه يعمل ويمكن التواصل مع مضيف آخر بالشبكة المحلية.
  4. Ping عناوين IP لمضيفين آخرين بنفس الـsubnet: لاختبار مشاكل الإعداد المحلي أو الرابط. إذا تعذّر الـping وكان الخطأ "destination unreachable"، تحققي من عدم وجود عنوان IP أو netmask خاطئ. إذا كانت صحيحة لكن الـping ما زال ينتهي بمهلة، اشتبهي بمشكلة أمنية (مثل إعداد أمان منفذ السويتش) أو مشكلة بطبقة Data Link أو Physical.
  5. Ping عنوان IP لمضيف بعيد: للتأكد من إمكانية التواصل عبر الراوتر. إذا تعذّر الوصول لعنوان بعيد، تحققي من إعداد الـdefault gateway بالمضيف المحلي لاستبعاد مشكلة gateway خاطئ. إذا كان الـgateway صحيحًا ويمكن عمل ping له، ابدئي التحقيق ببنية التوجيه (routing infrastructure).
⚠️ انتبهي أن ICMP قد يكون محجوبًا بجدار ناري أو برنامج أمان، خصوصًا عند عمل ping لمضيفين بعيدين. هذا الأسلوب المنهجي مناسب عند عدم القدرة على تشخيص السبب أو عند التحقق من إعداد IP جديد/مُعدَّل — لكن عمليًا، قد تبدئين مباشرة بـping لمضيف بعيد لتحديد المشكلة أو إعادة إنتاجها بسرعة.
ملخص الوحدة 4: IP يربط شبكات متعددة بعناوين فريدة؛ IPv4 = 32 bit/4 octets؛ الـsubnet = segment على طبقة الشبكة (L3)؛ أدوات TCP/IP للفحص والإعداد؛ IPv6 = ثمانية مجموعات 16-bit بصيغة hex؛ استكشاف الأخطاء يبدأ بفحص الإعداد المحلي ثم تسلسل ping من loopback حتى مضيف بعيد.

بروتوكولات التوجيه الديناميكي (Dynamic Routing Protocols): خوارزميات تحدّث معلومات المسار تلقائيًا وتضبط المسارات بين عقد الشبكة عبر توزيع معلومات الـtopology.

المزايا: قابلية التوسع، التكيّف مع تغيّرات الشبكة، وتقليل عبء الإدارة.

اعتبارات: تحتاج معالجة وذاكرة أكبر، والإعداد الصحيح مهم جدًا للأمان والكفاءة.

RIP (Routing Information Protocol)

بروتوكول قديم (legacy) يجد أفضل مسار باستخدام hop count كمقياس، بحد أقصى 15 hop. غير مناسب للشبكات الكبيرة وبطيء التقارب (convergence).

EIGRP (Enhanced IGRP)

بروتوكول distance-vector متقدم، يستخدم مقاييس (bandwidth, delay, load, reliability)، يدعم IPv4 وIPv6 معًا. ملكية Cisco وأكثر تعقيدًا بالإعداد.

OSPF (Open Shortest Path First)

بروتوكول link-state يحسب أقصر مسار عبر خوارزمية Shortest Path First، يدعم topologies معقدة، لكنه يحتاج تخطيطًا أدق وbandwidth أكثر من بروتوكولات distance-vector.

BGP (Border Gateway Protocol)

بروتوكول يمكّن الإنترنت من تبادل معلومات التوجيه بين autonomous systems. قابل للتوسع لحجم الإنترنت، يستخدم path vector، ويدعم CIDR.

ترجمة عناوين الشبكة — Network Address Translation

NAT Types · Edge Routers · PAT

NAT: يعدّل معلومات عنوان الشبكة في رؤوس الحزم أثناء عبورها، ما يزيد الأمان بإخفاء عناوين IP الداخلية عن الشبكات الخارجية، ويتيح لعدة أجهزة بالشبكة المحلية مشاركة عنوان IP عام واحد، وبالتالي يوفّر عناوين IP العامة.

NAT يترجم عناوين IP الخاصة المتعددة داخل الشبكة المحلية إلى عنوان IP عام واحد عند الخروج للإنترنت.

Dynamic NAT

يربط العناوين الداخلية بمجموعة (pool) من العناوين الخارجية ديناميكيًا — يسمح لعدد أكبر من الأجهزة بمشاركة نفس عناوين IP الخارجية.

Static NAT

يترجم عنوان IP داخلي واحد إلى عنوان IP خارجي واحد ثابت — يسمح باتصالات واردة (inbound) تبدأ من خارج الشبكة.

Edge Router: يقع عند حدود الشبكة المتصلة بشبكات خارجية (كالإنترنت)، يدير تدفق البيانات بين الداخل والخارج، يوجّه البيانات لوجهتها، وينفّذ NAT ويطبّق إجراءات الأمان.

  • CE (Customer Edge): عند حافة شبكة العميل، يربط الشبكة الداخلية بشبكة المزوّد ويعمل كحاجز أمني.
  • PE (Provider's Edge): عند حافة شبكة المزوّد، يركّز على حماية سرية بيانات العميل أثناء عبورها شبكة المزوّد.
PAT (Port Address Translation): شكل من NAT يسمح لعدة أجهزة داخلية بمشاركة عنوان IP عام واحد في نفس الوقت، عبر تمييز كل اتصال برقم منفذ (port) مختلف — الأشيع استخدامًا في راوترات SOHO.

الشبكات المحلية الافتراضية — Virtual LANs

VLAN: تُنشئ شبكات منفصلة منطقيًا داخل بنية تحتية فيزيائية واحدة.

  • Segmentation: تقسّم الشبكة لأجزاء معزولة صغيرة، بدون الحاجة لعتاد منفصل.
  • Flexibility: تجميع المستخدمين والأجهزة حسب الوظيفة أو القسم أو الفريق، بغض النظر عن الموقع الفيزيائي.
  • Simplified Administration: يمكن إدارة تغييرات/نقل الشبكة بسهولة دون تعديل التمديدات الفيزيائية.

VLAN IDs والعضوية: كل VLAN له معرّف فريد (VLAN ID)، وكل جهاز عضو في VLAN معيّن. الأجهزة تستخدم VLAN IDs لإدارة الترافيك، ويحتاج Inter-VLAN routing للتواصل بين VLANs مختلفة.

نفس السويتش الفيزيائي، لكن كل مجموعة منافذ (ports) معزولة منطقيًا في VLAN مختلف — كأنها شبكات منفصلة تمامًا رغم مشاركة نفس العتاد.

Port Tagging: طريقة لتوسيم حزم البيانات بمعرّف VLAN.

  • Tagged ports: مُهيّأة لاستقبال وفهم الحزم التي تحمل معرّف VLAN.
  • Untagged ports: تستقبل البيانات بدون معرّف VLAN.

بروتوكولات Transport وApplication

Implementing Network Services — TCP · UDP

دور طبقة Transport (L4): توصيل بيانات التطبيقات multiplexed فوق الاتصال الأساسي والعنونة والتوجيه اللي توفّرها الطبقات 1-3.

TCP (Transmission Control Protocol): ينقل البيانات بطريقة موثوقة (reliable) بين الأجهزة. للحفاظ على حالة الاتصال، يحتاج حقول رأس (header fields) كثيرة:

Source port, Destination port, Sequence number, Ack number, Data length, Flags, Window, Checksum, Urgent Pointer, Options

TCP Three-Way Handshake:

SYN←SYN + ACK←ACK←Connection Established

UDP (User Datagram Protocol): ينقل البيانات بطريقة غير مضمونة (non-guaranteed) بدون handshake أو تتبع حالة — أخف وأسرع لكن بدون ضمان وصول. حقول الرأس أبسط: Source port, Destination port, Message length, Checksum.

فرّقي: TCP = اتصال موثوق مع handshake وتتبع حالة (مثل الويب والبريد). UDP = إرسال سريع بدون ضمان (مثل البث الحي والـVoIP).

Explaining Application Services — TLS · NTP · PTP

TLS (Transport Layer Security) يوفر ثلاث خصائص أساسية:

  • Encryption: تشفير البيانات.
  • Authentication: تأكيد هوية السيرفر عبر الشهادات (certificates).
  • Integrity: التأكد أن البيانات لم تتغيّر أثناء النقل.

TLS Handshake:

Client Hello←Server Hello←Client Key Exchange←Session Key Established←Server Finished

NTP (Network Time Protocol): يزامن ساعات الأنظمة مع UTC عبر بروتوكول UDP على المنفذ 123.

  • Hierarchy: ينظّم الأجهزة هرميًا حسب بُعدها عن الساعة المرجعية (stratum).
  • Synchronization: يزامن الأجهزة عبر رسائل مُختَّمة زمنيًا (timestamped) بين الأقران.
  • Algorithms: يستخدم خوارزميات معقدة لحساب تأخير الشبكة والـjitter.

PTP (Precision Time Protocol): دقة زمنية أعلى من NTP، تُستخدم في العمليات الصناعية، شبكات 5G، الأجهزة الطبية، الخدمات المالية، والبث.

  • Grandmaster clock: المصدر الزمني الرئيسي بمجال PTP.
  • Boundary clock وOrdinary clock: أنواع ساعات أخرى بالتسلسل الهرمي.
  • الأدوار: TimeTransmitter, TimeReceiver, Grandmaster, Boundary.

Simple Network Management Protocol

SNMP: يعمل في طبقة Application، ويستخدم منفذي UDP 161/162.

وظائفه: مراقبة أجهزة الشبكة، اكتشاف أعطال الشبكة، وضبط الأجهزة عن بُعد.

إدارة الأحداث — Event Management

Network Device Logs · Syslog · SIEM

سجلات أجهزة الشبكة: مصادر بيانات لمراقبة الشبكة، استكشاف الأخطاء، والتدقيق الأمني. أنواعها: System Logs، Application Logs، Audit Logs، Performance/Traffic Logs.

استخدامات السجلات: تحديد مشاكل الشبكة وتحسين الأداء، تتبع الوصول غير المصرح به والانتهاكات (أمان/امتثال)، ومراجعة دورية مع تخزين آمن للسلامة والاستخدام الجنائي.

Log Collectors: تمركز وتبسيط إدارة سجلات الشبكة، عبر تجميع بيانات السجلات في مستودع واحد — الفوائد: إدارة مركزية، كفاءة، وقابلية التوسع.

Syslog: بروتوكول قياسي لإرسال رسائل السجل، يستخدم منفذ UDP 514، له PRI Code ومرونة عالية — منتشر جدًا ويسهّل التكامل بين الأنظمة.

ترتيب أولوية الأحداث والتنبيهات: تصنيف الأحداث من Emergency (0) إلى Debug (7) حسب الأهمية، والتنبيهات الآلية تُطلَق حسب شدة الحدث/العتبات/الشذوذ — يمنع الغرق بتنبيهات غير حرجة ويحدد أولوية الأحداث الحرجة.

تصاعديًا من الأخطر (يسار): 0 Emergency · 1 Alert · 2 Critical · 3 Error · 4 Warning · 5 Notice · 6 Informational · 7 Debug (الأقل أهمية).

SIEM (Security Information and Event Management): يحلل تنبيهات الأمان من التطبيقات وأجهزة الشبكة لحظيًا، يدمج إدارة معلومات الأمان (SIM) وإدارة أحداث الأمان (SEM).

وظائفه الأساسية: تجميع السجلات (Log Aggregation)، ربط الأحداث (Event Correlation)، والتنبيه (Alerting).

الفوائد: رؤية لحظية، اكتشاف واستجابة للتهديدات، إدارة الامتثال، تحسين وضع الأمان، وتقليل وقت الاستجابة للحوادث.

مراقبة الترافيك — Traffic Monitoring

Flow Data · Bandwidth Management · Traffic Shaping

Traffic Monitoring: مراقبة وتحليل مستمر لتدفق الترافيك عبر الشبكة لضمان الأداء والأمان الأمثل — يحدد اتجاهات حجم الترافيك، يراقب الأداء لاكتشاف الشذوذ، ويساعد بتخطيط السعة وتعديلات تصميم الشبكة.

مشاكل الأداء الشائعة: فقدان الحزم والتأخير والـjitter (يؤثر على جودة الخدمة QoS)، اختناقات bandwidth تُبطئ نقل البيانات، عتاد شبكة سيء الإعداد، وبنية تحتية قديمة.

Flow Data: معلومات مستخرَجة من حزم البيانات تعطي رؤية عن تدفق الترافيك — تشمل عناوين IP المصدر/الوجهة، أحجام الحزم، والطوابع الزمنية. ضرورية لتحليل الأداء واستكشاف الأخطاء، وتُستخدم في تحديد أنماط الترافيك واكتشاف الشذوذ.

أدوات اختبار الترافيك: تطبيقات تحاكي ترافيك الشبكة وتختبر أداء المكونات — تحدد اختناقات الشبكة وحدود السعة. تشمل مولّدات الحزم، محاكيات الشبكة، وأدوات قياس الإنتاجية. أمثلة: Wireshark, iperf, NetFlow Analyzer.

Bandwidth Management

تقنيات للتحكم بتدفق الترافيك لتحسين أو ضمان الأداء — تخصيص bandwidth بأولوية للخدمات الأساسية، منع الازدحام وضمان استخدام عادل، عبر rate limiting وtraffic policing.

Traffic Shaping

إعطاء أولوية للترافيك لضمان حصول التطبيقات الحرجة على bandwidth المطلوب — بتأخير الحزم لتنظيم التدفق وتقليل الازدحام. أدوات: QoS، DiffServ، وMPLS.

مفاهيم الأمان — Security Concepts

Explaining Network Security Concepts — CIA Triad · Vulnerability/Threat/Risk · Encryption

CIA Triad: النموذج المرجعي لأمان المعلومات، يتكوّن من:

  • Confidentiality: منع الوصول غير المصرح به للبيانات.
  • Integrity: التأكد أن البيانات لم تتغيّر أو تُعبَث بها.
  • Availability: ضمان توفر الأنظمة والبيانات عند الحاجة.
CIA Triad: كل قرار أمني يوازن بين ثلاثة أهداف — منع الوصول غير المصرح به، ضمان عدم التلاعب بالبيانات، وضمان توفرها عند الحاجة.

Security Audit: تقييم منهجي لأمان نظام المعلومات، يقيس التوافق مع معايير الأمان، يحدد نقاط القوة والضعف، ويوضّح مجالات التحسين.

أنواع تقييمات الأمان: Compliance Audits (التحقق من الالتزام بالقوانين والمعايير) · Risk-Based Audits (تحديد وترتيب التهديدات/الثغرات حسب الأولوية) · Technical Audits (فحص عميق للبنية التقنية).

إدارة المخاطر (Risk Management): تحديد الأصول الحرجة (الوظائف/الأصول الأساسية للعمل)، تحليل أثر الأعمال (BIA) لتقييم الخسائر المحتملة، واستراتيجيات تخفيف توازن تكلفة الضوابط الأمنية مقابل المخاطر لتحديد مستوى الخطر المقبول.

الامتثال التنظيمي (Regulatory Compliance): ضمان الالتزام بكل القوانين واللوائح المتعلقة بالصناعة، لحماية البيانات والخصوصية وسلامة المعاملات.

GDPR

يخص جمع/معالجة البيانات الشخصية داخل الاتحاد الأوروبي — موافقة مستنيرة وحقوق البيانات.

PCI DSS

يخص المؤسسات المتعاملة مع بطاقات الدفع — معايير لحماية بيانات حاملي البطاقات.

التشفير (Encryption): تحويل البيانات المقروءة (plaintext) لصيغة مشفّرة (ciphertext) لا يصل لها إلا من يملك مفتاح فك التشفير — يضمن سرية البيانات.

  • Encryption Algorithm: يحوّل plaintext لciphertext ويحتاج مفتاحًا لفك التشفير (لحماية الإيميلات/الملفات).
  • Cryptographic Hash Algorithm: يحوّل نصًا لـhash بطول ثابت لا يمكن عكسه (لتخزين كلمات المرور والتحقق من سلامة البيانات).

الثغرات (Vulnerabilities): عيوب في تصميم البرمجيات تسمح بتجاوز الحماية أو تسبب أعطالًا — أسبابها: سوء إعداد، ممارسات ضعيفة، عيوب تصميم. أثرها: تنفيذ كود عشوائي، تثبيت برامج ضارة، اختراق إعدادات الأمان.

  • Unpatched/Legacy Systems: تشكّل خطرًا كبيرًا بسبب نقص التحديثات والدعم.

تهديدات وهجمات الشبكة — Network Threats and Attacks

External/Internal Threats · Enumeration · DoS/DDoS · Malware

External Threats

هجمات من أفراد/جهات خارج المؤسسة (هاكرز، مجرمون سيبرانيون، تجسس) — غالبًا متطورة ومستهدفة. المكافحة: جدران نارية، أنظمة IDS، تدقيق خارجي، وتدريب توعوي.

Internal Threats

تنشأ من داخل المؤسسة (موظفون، مقاولون، شركاء) — تسريب بيانات عرضي، سرقة بيانات متعمدة، تخريب. أصعب اكتشافًا بسبب الوصول الشرعي. المكافحة: صلاحيات قائمة على الدور، مراقبة نشاط المستخدم.

هجمات الاستكشاف (Enumeration Attacks):

  • Footprinting: اكتشاف هيكلية الشبكة وإعدادات الأمان عبر الهندسة الاجتماعية أو فحص المنافذ.
  • Fingerprinting: تحديد إصدارات النظام/البرامج، وسبر الثغرات.

هجمات حجب الخدمة (DoS): تهدف لتعطيل الخدمة ومنع وصول المستخدمين، عبر استنزاف الموارد أو تشبّع bandwidth أو استغلال ثغرات البرمجيات — تطورت لهجمات DDoS معقدة باستخدام الـbotnets.

أمثلة DDoS: ICMP Flood (إغراق بحزم ICMP) · SYN Flood (استغلال TCP handshake لمنع الوصول الشرعي) · DNS Amplification (استغلال سيرفرات DNS سيئة الإعداد).

مكافحة DDoS: كشف مبكر لأنماط الترافيك غير الطبيعية، تصفية الترافيك (جدران نارية/IDS)، خطة استجابة جاهزة، وتكرار (redundancy) الشبكة لتقليل التوقف.

Botnet: شبكة من الأجهزة المخترَقة تُدار عن بُعد للاستخدام الخبيث — أنواعها: DDoS botnets، Spam botnets، Banking trojan botnets. المكافحة: جدران نارية ومضاد فيروسات، تحليل الترافيك غير الطبيعي، عزل الأجهزة المخترَقة، وتوعية المستخدمين.

Malware: برمجيات ضارة تعطّل أو تضرّ الأنظمة — أنواعها: Viruses/Worms، Trojan، PUPs/PUAs. تتكون من vectors (طرق الإصابة والانتشار) وpayloads (الأفعال الضارة المنفَّذة كالتجسس أو الفدية).

Fileless Malware: تهديد متطور، لا يترك كودًا على القرص، صعب الاكتشاف — يقيم في الذاكرة ويستخدم أدوات سكريبت (PowerShell, WMI)، يحافظ على استمراريته عبر تعديلات الـregistry بدون ملفات — جزء من هجمات APT/AVT متقدمة.

هجمات الانتحال — Spoofing Attacks

On-Path Attacks · MAC Flooding · VLAN Hopping

Spoofing: التنكّر كجهة أخرى للحصول على وصول غير مصرّح به، لخداع المستخدمين/الأجهزة وتجاوز الحماية وسرقة البيانات أو نشر برمجيات ضارة. أنواعها: IP spoofing، ARP spoofing، Email spoofing.

كل ترافيك بين Client وServer يمر فعليًا عبر المهاجم في المنتصف دون علم الطرفين — فيستطيع قراءته أو تعديله قبل تمريره.

On-Path Attacks (رجل في المنتصف): تعترض وربما تُعدّل اتصال طرفين دون اكتشاف — لسرقة معلومات حساسة أو حقن برمجيات ضارة. أنواع شائعة: Session hijacking, SSL stripping, DNS spoofing, Wi-Fi eavesdropping, ARP spoofing.

MAC Flooding Attacks: تُغرق جدول CAM بالسويتش بعدد هائل من عناوين MAC، ما يسبب فشل السويتش وبثّ الترافيك للجميع — الهدف: التنصت على ترافيك غير متاح عادة. الأنواع: Random, Incremental, Targeted MAC flooding.

VLAN Hopping Attack: استغلال ثغرات إعداد VLAN بالسويتش لإرسال حزم لـVLAN بدون صلاحية وصول — لتجاوز الحماية والوصول لشبكات مقيّدة. النوعان: Switch Spoofing وDouble Tagging.
MODULE 9 · LESSON 9.4

هجمات الأنظمة المارقة — Rogue System Attacks

Rogue Devices · Rogue DHCP · DNS Attacks

Rogue Devices and Services: عتاد أو برمجيات غير مصرّح بها تتصل بالشبكة بدون إذن، وقد تسبب مخاطر أمنية جسيمة — وصول غير مصرح به، نية خبيثة، اعتراض وتلاعب بالبيانات.

Rogue DHCP Server: سيرفر DHCP غير مصرّح به يوزّع إعدادات شبكة خاطئة على العملاء — يُسبب توزيع إعدادات غير صالحة، إعادة توجيه الترافيك، وهجمات on-path.

DNS Attacks: هجمات تستهدف نظام DNS، تُضعف سلامة وتوفّر خدمات الإنترنت — تشمل تعطيل الخدمة، اختطاف النطاقات (domain hijacking)، وتسميم الذاكرة المؤقتة (cache poisoning).

الهندسة الاجتماعية — Social Engineering

Social Engineering Types · Password Attacks

Social Engineering: تقنية تلاعب يستخدمها مجرمو الإنترنت لاستغلال الثغرات البشرية، لا التقنية — لخداع الأفراد ودفعهم للكشف عن معلومات سرية أو شخصية. فعّالة جدًا لأنها تستغل ميل الناس الطبيعي للثقة، ونجاحها يعتمد على ظهور المهاجم بمظهر موثوق أو ذي سلطة.

أنواع هجمات الهندسة الاجتماعية:

  • Shoulder Surfing: التجسس على شاشة/لوحة مفاتيح الضحية مباشرة.
  • Dumpster Diving: البحث في المخلفات عن معلومات حساسة.
  • Tailgating/Piggybacking: دخول منطقة مقيّدة بمتابعة شخص مصرّح له.
  • Phishing: رسائل خادعة (بريد/رسائل) لانتزاع معلومات أو دفع الضحية لفعل ضار.

Dictionary Attacks

تُجرِّب كل كلمات القاموس — تستهدف كلمات المرور الضعيفة والبسيطة.

Brute Force Attacks

تُجرِّب كل تركيبات الأحرف الممكنة — تستهلك وقتًا طويلًا لكنها تكسر أي كلمة مرور نظريًا.

ملخص الوحدة 9: السياسات والضوابط تُبنى على CIA Triad؛ التقييم والمراقبة المستمرة للثغرات والتهديدات والمخاطر ضروريان؛ توعية المستخدمين بأنواع الهجمات (footprinting, spoofing, DoS, DNS manipulation, VLAN hopping, malware, password cracking, social engineering) خط دفاع أساسي.

المصادقة — Authentication

Applying Network Security Features — AAA · Authentication Factors · SSO · Kerberos

مفاهيم AAA (تشبيه بطاقة صعود الطائرة):

  • Identity: حساب أو معرّف يمثّل مستخدمًا/جهازًا/عملية بشكل فريد على الشبكة — من يدّعي أنه هو.
  • Authentication: عامل/عوامل تثبت أن الشخص هو من يدّعي — إثبات الهوية.
  • Authorization: الحقوق والصلاحيات الممنوحة داخل النظام — أين مسموح له الذهاب وأي مستوى وصول.
  • Accounting: تتبّع الاستخدام المصرّح/غير المصرّح به للمورد — تسجيل النشاط.
أولًا تُحدَّد الهوية (من أنت)، ثم تُثبَت (Authentication)، ثم تُمنح الصلاحيات (Authorization)، وأخيرًا يُسجَّل كل نشاط (Accounting).

Single Sign-On (SSO): تسجيل دخول واحد يمنح وصولًا لعدة تطبيقات/خدمات (مثل حساب Microsoft الواحد للوصول لـTeams, Outlook, OneDrive, SharePoint) بدون تكرار تسجيل الدخول لكل خدمة.

Kerberos: بروتوكول مصادقة SSO يستخدم نظام tickets (عبر Ticket Granting Service) للتحقق من هوية المستخدم مرة واحدة، ثم استخدام التذاكر للوصول للخدمات المختلفة بدون إعادة إدخال بيانات الدخول.

التفويض وإدارة الحسابات

Authorization and Account Management — Access Control Models · PAM

DAC (Discretionary Access Control)

وصول يتحكم به مالك المورد نفسه — هو من يقرر من يصل لملفاته/موارده.

RBAC (Role-Based Access Control)

الوصول يُمنح حسب الدور الوظيفي للمستخدم داخل المؤسسة، لا بشكل فردي.

مصطلحات إدارة الوصول:

  • Privileged Account: حساب للتغييرات الجوهرية بالنظام.
  • PAM (Privileged Access Management): ضوابط لمنع إساءة استخدام الحسابات المميّزة.
  • Least Privilege: منح المستخدمين الصلاحيات الكافية فقط لأداء عملهم، لا أكثر.
  • Separation of Duties: تقسيم المهام الحساسة بين عدة أشخاص لمنع سوء الاستخدام.
مثال تطبيقي: مدير الأنظمة يحتاج وصولًا لإعدادات السيرفرات والأمان، بينما مندوب المبيعات يحتاج فقط لبرنامج المبيعات وقاعدة بيانات العملاء — هذا هو مبدأ Least Privilege عمليًا.

أمان السويتش — Switch Security

NAC · Port Security

مصطلحات أساسية: NAC (Network Access Control): نظام لمصادقة وتفويض الوصول للشبكة. Switch: يربط ويدير الاتصال على الشبكة. Switch Ports: منافذ مخصصة على السويتش لتوصيل الأجهزة.

إجراءات أمان المنافذ (Port Security):

  • تأمين الوصول الفيزيائي للسويتش.
  • تحديث الـfirmware بانتظام.
  • تعطيل المنافذ غير المستخدَمة.
  • إعداد MAC filtering لتحديد الأجهزة المسموح لها.
  • تفعيل Router Advertisement (RA) Guard.
  • إعداد DHCP snooping لفحص أصالة ترافيك DHCP.
  • تطبيق مصادقة 802.1x (EAP).
سيناريو: جهاز غير مصرّح به اتصل بغرفة السيرفرات → أمّني الوصول الفيزيائي (خزائن قابلة للقفل) → عطّلي المنافذ غير المستخدَمة → فعّلي MAC filtering → فعّلي DHCP snooping لفحص أصالة ترافيك DHCP.

الحلول: تحليل سجلات ارتباط الـAP، ضبط موقع/قوة الـAP لتغطية متوازنة، وإجراءات أمنية لكشف هجمات الانتحال.

الحلول: توزيع استراتيجي لعدة APs، تحديد عدد أقصى للأجهزة لكل AP، أدوات تشكيل الترافيك (traffic shaping)، تعيين قنوات ديناميكي، ومراقبة مستمرة بأدوات Wi-Fi للمؤسسات.

Comparing Remote Access Methods — WAN and Internet Connectivity

WAN مقابل LAN: الـWAN ينقل البيانات لمسافات كبيرة، غالبًا عبر شبكات عامة. الـLAN يغطي مناطق أصغر ومحلية. Enterprise WAN: شبكة لمؤسسة واحدة تمتد لمناطق جغرافية واسعة، تستخدم بنية اتصالات عامة.

  • Network Layer: يستخدم IP للعنونة، يربط مواقع العميل والمزوّد عبر راوترات CE وPE، ويخصص عناوين IPv4/IPv6 عامة للتعريف العالمي.

ألياف بصرية حتى الأرصفة القريبة من المباني، ثم كيبل نحاسي/coax للمرحلة الأخيرة — سرعة وموثوقية أعلى من النحاس التقليدي، لكن أقل قليلًا من FTTP.

FTTP (Fiber to the Premises)

ألياف بصرية حتى المبنى مباشرة — أعلى سرعة ممكنة، بنية مستقبلية قابلة للتوسع، لكن تكلفة تركيب أعلى وقد لا تتوفر بكل المناطق.

مقارنة طرق الوصول عن بُعد — VPN

Tunneling Protocols · IPSec · Client-to-Site & Site-to-Site VPN

سياسة الوصول عن بُعد: وصول مصرّح به فقط مع تحقق قوي من الهوية، استخدام VPNs وتشفير البيانات أثناء النقل، تأمين الأجهزة البعيدة (تحديثات، مضاد فيروسات)، وصول قائم على الدور، سجلات وصول مفصّلة، وتحديثات أمنية دورية لأجهزة RAS.

بروتوكولات النفق (Tunneling Protocols): تمرّر بيانات خاصة بأمان عبر شبكات عامة، عبر تغليف الحزم داخل حزم أخرى، لإنشاء أنفاق آمنة تضمن وصولًا حصريًا بين المرسل والمستقبل.

البروتوكولطبقة OSIالخصائص
PPPData Linkللخطوط الرقمية، يفتقر لأمان مدمج
GRENetworkتغليف بروتوكولات متعددة
IPSecNetworkتأمين IP عبر المصادقة والتشفير
TLS/DTLSSessionأمان بعبء إضافي أعلى، تُستخدم بـVPN للاتصال المشفّر والموثّق عن بُعد

أوضاع IPSec:

  • Transport Mode: يُستخدم غالبًا داخل شبكة خاصة، يشفّر الحمولة (payload) فقط. AH يوفّر سلامة رأس IP، وESP يشفّر الحمولة للسرية.
  • Tunnel Mode: مثالي لشبكات VPN وتأمين الاتصالات عبر شبكات عامة — يشفّر الحزمة كاملة بما فيها الرأس، ويُغلّفها داخل حزمة IP جديدة.

خطوات إعداد IPSec: اختيار Transport أو Tunnel حسب متطلبات الشبكة → تحديد AH و/أو ESP → إدارة مفاتيح تلقائية عبر IKE أو يدوية → تعريف سياسات التعامل مع الترافيك → اختبار الإعداد دوريًا.

IKE (Internet Key Exchange): بروتوكول IPSec للتواصل الآمن عبر الإنترنت، أساسي لبنية VPN موثوقة — يتفاوض وينشئ SAs، مصادقة متبادلة، وتبادل مفاتيح تشفير.

  • IKEv1: VPN موقع-لموقع ومضيف-لمضيف، قناة موثقة آمنة.
  • IKEv2: يدعم EAP للمصادقة، إعداد أبسط، اجتياز NAT أفضل، MOBIKE للاتصال المتنقل — المفضّل لحلول VPN الحديثة.

Client-to-Site VPN

عملاء أفراد يتصلون بشبكة الشركة عبر الإنترنت العام. المكونات: VPN Client (البرنامج/الجهاز المبادِر) وVPN Gateway (راوتر مفعَّل بـVPN عند حافة الشبكة) — مثالي للعمل عن بُعد.

Site-to-Site VPN

اتصال دائم بين شبكتين — أمان عالٍ، إدارة مبسّطة (بدون إعداد كل جهاز فرديًا)، وقابلية توسع. حالات استخدام: ربط الفروع، الدمج والاستحواذ، شبكات IIoT، والتكامل السحابي.

Client-to-Site: مستخدم فردي يتصل عبر نفق مشفّر لشبكة الشركة
Site-to-Site: نفق دائم يربط شبكتين كاملتين ببعض

بروتوكولات VPN: SSL/TLS VPN (نفق آمن بشهادات، مثل SSTP) وL2TP/IPSec (أمان قوي منتشر). بروتوكول PPTP مُهجَّر (deprecated) لثغراته الأمنية.

Split Tunnel مقابل Full Tunnel: توازن بين الوصول المباشر للإنترنت والحاجة الأمنية — Split يمرر فقط ترافيك الشركة عبر النفق، Full يمرر كل الترافيك.

Clientless VPN: وصول لموارد الشبكة عبر المتصفح، بدون الحاجة لبرنامج VPN مخصص، باستخدام HTML5 وWebSockets — يبسّط الوصول، يعزل الجلسة داخل المتصفح، وفعّال من ناحية التكلفة. أمثلة: Microsoft RDS، Citrix، Apache Guacamole.

الإدارة عن بُعد — Remote Management

SSH · Telnet · RDP · Console/OOB · Jump Boxes

Remote Host Access: يتيح التحكم عن بُعد بالحواسيب وأجهزة الشبكة — إعداد الأجهزة، إدارة السيرفرات/المستخدمين، عبر واجهة رسومية (GUI) أو طرفية (terminal).

SSH (Secure Shell): بروتوكول اتصال آمن مشفّر بالكامل — للوصول عن بُعد للسيرفرات وأجهزة الشبكة، نقل ملفات آمن، جلسات طرفية، وتنفيذ أوامر.

Telnet: محاكاة طرفية للوصول لنظام بعيد، يستمع افتراضيًا على المنفذ TCP 23. اتصالاته (بما فيها كلمات المرور) غير مشفرة — عرضة للتنصت وإعادة التشغيل. أفضل الممارسات: تجنّبيه للمهام الحساسة، عطّليه واحجبي المنفذ 23، واستخدمي SSH بدلًا منه.

RDP (Remote Desktop Protocol): بروتوكول مايكروسوفت للتحكم بسطح المكتب عن بُعد، منفذ TCP 3389، يدعم واجهة رسومية، مؤمّن بتشفير وNLA (Network Level Authentication). أفضل الممارسات: تجنّب استخدامه من أجهزة منخفضة الثقة، استخدام SAW للاتصالات الإدارية. بدائل: TeamViewer، VNC، Citrix.

Console Connections

اتصال مباشر لإعداد/استكشاف أخطاء أجهزة الشبكة، عبر كيبل console (rollover) متصل بجهاز به برنامج محاكي طرفية — لإعداد الأجهزة عند تعذّر الوصول عبر الشبكة.

OOB (Out-of-Band) Management

قناة مخصصة لإدارة الجهاز بمعزل عن ترافيك البيانات — وصول آمن وموثوق للوظائف الإدارية خصوصًا أثناء انقطاع الشبكة. أمثلة: منفذ AUX، منفذ إدارة IP منفصل.

كل الوصول الإداري يمر عبر الـJump Box فقط — السيرفرات مُعدَّة لرفض أي اتصال مباشر من خارج الـJump Box.

Jump Box: نقطة وصول آمنة لإدارة سيرفرات/أجهزة داخل subnet محمي أو شبكة سحابية — تعمل كمدخل وحيد يقلل سطح الهجوم. يتصل المسؤولون بالـJump Box عبر SSH/RDP، ومنها فقط يمكن الوصول لواجهات الإدارة — سيرفرات التطبيقات مُعدَّة لقبول اتصالات من الـJump Box فقط.

API Connection Methods: أتمتة عبر سكريبتات بدل الإعداد اليدوي — ممارسات أمنية: مصادقة قوية، تجنّب حساب root للأتمتة، مفاتيح سرية للوصول البرمجي، HTTPS للتواصل، ومبدأ Least Privilege لحسابات الأتمتة.

شبكات مراكز البيانات والتخزين

Summarizing Cloud Concepts — Datacenter and Storage Networks

مكونات تصميم شبكة مركز البيانات الحديث: Virtualization (شبكات رشيقة وقابلة للتوسع)، Overlay Networks (ترافيك آمن ومرن بين السيرفرات)، Zero Trust Architecture (مصادقة/تفويض لكل طلب)، وميزات High Availability (شبكة، طاقة، مناخ، تحكم بالوصول).

North-South Traffic

وصول العملاء الخارجيين لموارد مركز البيانات.

East-West Traffic

تواصل السيرفرات ببعضها داخل مركز البيانات — يحتاج أمانًا متقدمًا وإدارة ترافيك فعّالة.

Spine and Leaf Topology: هيكلية ثنائية الطبقة لتحسين تدفق ترافيك مركز البيانات.

  • Spine Layer: العمود الفقري بسويتشات توزيع عليا، متصلة بكل سويتشات الـleaf لكن ليس ببعضها.
  • Leaf Layer: سويتشات وصول متصلة بكل سويتش spine بهيكلية full mesh — مسارات مباشرة للأجهزة بدون اتصالات بين الـleaf switches نفسها.

فوائدها: latency متوقعة (قفزة واحدة من أي سيرفر للعمود الفقري)، موازنة حمل وfailover (مسارات متعددة زائدة)، تصميم بلا حلقات (يُلغي الحاجة لـSTP)، قابلية توسع وتكرار (إضافة عقد spine/leaf بسهولة)، واتصال عالي السرعة (سويتشات ToR).

كل leaf switch متصل بكل spine switch (full mesh) — أي سيرفر يصل لأي سيرفر آخر بقفزة واحدة فقط عبر العمود الفقري.

SAN (Storage Area Network): شبكة مخصصة لتوفير وصول لتخزين بيانات موحّد على مستوى الكتلة (block-level)، تفصل موارد التخزين عن الشبكة المحلية.

مكوناتها: أجهزة تخزين (RAID arrays، مكتبات أشرطة)، SAN Fabric (سويتشات وdirectors تربط السيرفرات بأجهزة التخزين)، وSAN Software (أدوات إدارة وإعداد).

فوائدها: توفر عالٍ، قابلية توسع، latency منخفض وthroughput عالٍ. حالات الاستخدام: إدارة قواعد البيانات، استمرارية الأعمال، والتخزين السحابي.

Fibre Channel (FC): بروتوكول نقل بيانات عالي السرعة، العمود الفقري لشبكات SAN (الإملاء البريطاني "Fibre" يميّزه عن كيابل الألياف البصرية "fiber"). المكونات: Initiators (سيرفرات بـHBA)، Targets (منافذ أجهزة التخزين)، وFC Switches. المزايا: أداء، مرونة، سرعة، وآليات QoS.

بيئات الشبكات الحديثة — Modern Network Environments

IaC · SDN · Overlay Networks · Zero Trust · SASE

IaC (Infrastructure as Code): إدارة البنية التحتية عبر ملفات تعريف قابلة للقراءة آليًا — كود لإدارة وتوفير البنية التحتية تلقائيًا وبأمان، لنشر متسق وسريع وفعّال التكلفة.

أدوات IaC: Terraform (كود إعلاني لتوفير أي سحابة/بنية)، Ansible (لغة إعلانية للأتمتة)، Chef (recipes/cookbooks)، Puppet (نهج إعلاني)، AWS CloudFormation.

Source Control: طريقة لإدارة وتتبّع تغييرات الكود بتطوير البرمجيات — أساسي للمشاريع التعاونية وسلامة الكود. المكونات: version control، central repository، branching، وconflict identification.

SDN (Software-Defined Networking): يبسّط إدارة الشبكة بفصل وظائف التحكم والتوجيه، يسمح بالبرمجة المباشرة للتحكم بالشبكة.

  • SDN Controller: "دماغ" الشبكة.
  • Southbound APIs: التواصل بين الـcontroller والأجهزة.
  • Northbound APIs: الواجهة بين الـcontroller وتطبيقات الأعمال.

حالات استخدام: افتراضية الشبكة، الحوسبة السحابية، إدارة مراكز البيانات، وإنترنت الأشياء.

Overlay Network: شبكة افتراضية مبنية فوق شبكة فيزيائية موجودة، تتيح روابط منطقية بين العقد. أمثلة: VPNs، بروتوكولات تغليف مثل VXLAN (لتطبيقات مراكز البيانات) — تسهّل تقسيم الشبكة وعزلها.

SD-WAN: نهج مبتكر لتصميم WAN المؤسسات — اتصال محسّن بين الفروع ومراكز البيانات والسحابة، تحسين تدفق الترافيك بالأتمتة والإدارة المركزية وأنفاق IPsec آمنة.

Zero Trust Architecture — المبادئ الأساسية:

  • Assume No Trust: لا يُوثَق بأي جهة (مستخدم/جهاز) افتراضيًا، سواء داخل الشبكة أو خارجها.
  • Continuous Verification: مصادقة وتفويض مستمر لكل جلسة/معاملة.
  • Least Privilege Access: أقل صلاحيات ممكنة لإنجاز المهمة، لتقليل مسارات الهجوم المحتملة.

التطبيق: مصادقة/تفويض قائم على السياسة مركزيًا، فصل مستويات التحكم والبيانات، ومناطق ثقة ضمنية وتقسيم دقيق (microsegmentation).

SASE (Secure Access Service Edge): بنية سحابية تجمع وظائف الشبكة والأمان بانتشار عالمي — تدمج SD-WAN مع SSE (Secure Service Edge). وظائف SSE تشمل Zero Trust وCASB (Cloud Access Security Broker) الذي يفرض سياسات الأمان، يفحص البرمجيات الضارة، ويراقب النشاط — عبر Forward Proxy، Reverse Proxy، أو API.
