مفهوم أمن المعلومات — CIA Triad

Information Security — The CIA Triad

الأساس الذي يُبنى عليه كل قرار أمني في الشهادة كلها

The foundation every security decision in the whole certification is built on

أمن المعلومات (Information Security) يقوم على أربع خصائص أساسية يجب حمايتها في أي نظام. الثلاث الأولى تُعرف بـCIA Triad:

Information Security rests on four core properties that must be protected in any system. The first three are known as the CIA Triad:

  • Confidentiality (السرية): المعلومة تُقرأ فقط من قِبل الأشخاص المصرّح لهم (authorized persons) — تُحقَّق غالبًا عبر التشفير (encryption) وضبط الوصول.
  • Integrity (السلامة): البيانات تُخزَّن وتُنقل كما هي، وأي تعديل عليها لازم يكون مصرَّحًا به — تُحقَّق عبر hashing والتوقيع الرقمي.
  • Availability (التوفر): المعلومة متاحة للأشخاص المصرَّح لهم عند الحاجة — لا تُهمَل رغم إنها أقل خاصية يُتحدَّث عنها.
  • Confidentiality: information should only be read by authorized persons — typically enforced via encryption and access control.
  • Integrity: data is stored and transferred as intended, and any modification must be authorized — enforced via hashing and digital signatures.
  • Availability: information is accessible to authorized people when needed — don't overlook this property just because it's discussed less.

وتضاف لها خاصية رابعة مهمة: Non-repudiation (عدم الإنكار) — الشخص لا يستطيع إنكار أنه أنشأ أو عدَّل بيانات معينة (يُحقَّق عبر التوقيع الرقمي وسجلات المراجعة).

A fourth important property is added: Non-repudiation — a person cannot deny creating or modifying data (enforced via digital signatures and audit logs).

C = Confidentiality (السرية) · I = Integrity (السلامة) · A = Availability (التوفر) — مثلث CIA + خاصية رابعة: Non-repudiation
C = Confidentiality · I = Integrity · A = Availability — the CIA triangle, plus a fourth property: Non-repudiation
اختصار بديل مفيد للحفظ: PAIN = Privacy, Authentication, Integrity, Non-Repudiation. لا تخلطي بين "الأمن" Security و"الخصوصية" Privacy — سيأتي الفرق بينهما لاحقًا بالمنهج.
A useful alternative mnemonic: PAIN = Privacy, Authentication, Integrity, Non-Repudiation. Don't confuse "Security" with "Privacy" — the distinction is covered later in the course.

أطر العمل الأمنية — NIST Cybersecurity Framework

Cybersecurity Framework — NIST CSF

تنظّم كيف تدير المؤسسة عملياتها الأمنية، ثم تحليل الفجوات لقياس مدى الالتزام بها

Organizes how a business runs its security operations, followed by gap analysis to measure compliance with it

إطار العمل (Framework): مجموعة إرشادات وأفضل ممارسات تساعد المؤسسة على بناء وتقييم برنامجها الأمني. أشهرها NIST Cybersecurity Framework (CSF) الصادر عن المعهد الوطني الأمريكي للمعايير والتقنية.

Framework: a set of guidelines and best practices that help an organization build and assess its security program. The best-known is the NIST Cybersecurity Framework (CSF), published by the US National Institute of Standards and Technology.

يقسّم NIST CSF العمليات الأمنية إلى وظائف أساسية (functions) متسلسلة تغطي دورة حياة الحماية كاملة:

NIST CSF splits security operations into core, sequential functions that cover the full protection lifecycle:

Identify← Protect← Detect← Respond← Recover
الوظيفةماذا تعني
FunctionWhat It Means
Identifyفهم الأصول (assets)، المخاطر، وسطح الهجوم — لا تقدرين تحمين ما لا تعرفينه
IdentifyUnderstand assets, risks, and attack surface — you can't protect what you don't know exists
Protectتطبيق الضوابط الوقائية: التشفير، ضبط الوصول، التدريب
ProtectApply preventive controls: encryption, access control, training
Detectاكتشاف الحوادث الأمنية عند وقوعها عبر المراقبة والتنبيهات
DetectDiscover security incidents as they happen via monitoring and alerts
Respondاحتواء الحادثة والتعامل معها فور اكتشافها
RespondContain and act on the incident once it's discovered
Recoverاستعادة الأنظمة والخدمات لوضعها الطبيعي بعد الحادثة
RecoverRestore systems and services back to normal after the incident
لاحظي أن ترتيب الوظائف الخمس يطابق تسلسل التعامل مع أي حادثة أمنية منطقيًا: تعرفين أصولك أولًا، تحمينها، تكتشفين الاختراق، تستجيبين له، ثم تتعافين. هذا الترتيب نفسه يتكرر بمفاهيم لاحقة في المنهج مثل Incident Response.
Notice the five functions follow the same logical sequence as handling any security incident: know your assets first, protect them, detect a breach, respond to it, then recover. This same sequence reappears later in the course under Incident Response.

تحليل الفجوات — Gap Analysis

Gap Analysis

بعد تبنّي إطار عمل، تحتاج المؤسسة معرفة أين تقف فعليًا مقارنة بما يتطلبه الإطار — هذا هو Gap Analysis: مقارنة الوضع الحالي (current state) بالوضع المستهدف (desired state) لتحديد الفجوات (gaps) التي تحتاج معالجة.

After adopting a framework, an organization needs to know where it actually stands relative to what the framework requires — this is Gap Analysis: comparing the current state to the desired state to identify the gaps that need addressing.

قد تتبنى المؤسسة إطار عمل لأنه أفضل ممارسة، أو لأن قانونًا أو جهة تنظيمية (regulatory requirement) يفرضه عليها. تحليل الفجوات يُستخدم لاحقًا كمدخل أساسي لإدارة المخاطر (risk management)، وهو موضوع مفصّل لاحقًا في المنهج.

An organization might adopt a framework because it's best practice, or because a law or regulatory requirement mandates it. Gap analysis later feeds directly into risk management, a topic covered in detail later in the course.

ضبط الوصول — Access Control

Access Control

الفرق بين "من أنت؟" و"أثبتي أنك من تدّعين"

The difference between "who are you?" and "prove you are who you claim"

Identification

عملية إثبات الهوية (identity proofing) وإنشاء حساب مستخدم لأول مرة — تحدث مرة واحدة عند التسجيل.

The process of identity proofing and creating a user account for the first time — happens once at enrollment.

Authentication

العملية التي تُثبت أن الحساب يُستخدم فعلًا من قِبل الشخص الذي أُنشئ له — تحدث في كل مرة يسجّل فيها الشخص الدخول.

The process that proves the account is being accessed by the person it was created for — happens every time someone logs in.

مصطلح IAM (Identity and Access Management) يعكس أهمية مكوّن Identification، وهو مصطلح أشمل من إطار العمل الأقدم AAA:

The term IAM (Identity and Access Management) reflects the importance of the Identification component, and is broader than the older AAA framework:

المكوّنيعني ماذا
ComponentWhat It Means
Authenticationإثبات هوية المستخدم (كلمة مرور، بصمة، شهادة رقمية...)
AuthenticationProving the user's identity (password, fingerprint, digital certificate...)
Authorizationتحديد ما يُسمح للمستخدم فعله بعد إثبات هويته (صلاحيات)
AuthorizationDetermining what the user is allowed to do once authenticated (permissions)
Accountingتسجيل ما فعله المستخدم فعليًا (سجلات ومراجعة)
AccountingLogging what the user actually did (logs and audit trail)
سؤال اختبار كلاسيكي: "ما الفرق بين Identification وAuthentication؟" ← Identification = إنشاء الحساب لأول مرة، Authentication = إثبات أن مستخدم الحساب هو صاحبه الحقيقي في كل دخول. تفاصيل أنظمة المصادقة ونماذج التفويض ستُشرح بالتفصيل لاحقًا بالمنهج — هذا فقط نظرة عامة تأسيسية.
Classic exam question: "What's the difference between Identification and Authentication?" ← Identification = creating the account for the first time, Authentication = proving the account's real owner is using it on every login. Authentication systems and authorization models are covered in full detail later — this is only a foundational overview.

فئات الضوابط الأمنية — Security Control Categories

Security Control Categories

الفئة تصف كيف يُنفَّذ الضابط الأمني

A category describes how a control is implemented

إشراف على النظام
Oversight of the system
يعتمد على شخص للتنفيذ
Relies on a person to implement
يُنفَّذ بالأنظمة والبرمجيات
Implemented in systems/software
يضبط الوصول للمبنى والأجهزة
Mediates access to premises/hardware
  • Managerial (إداري): يمنح إشرافًا على النظام — مثل السياسات (policies) وإجراءات إدارة المخاطر.
  • Operational (تشغيلي): يعتمد على شخص لتنفيذه — مثل التدريب الأمني والتحقق من الالتزام بالسياسة يدويًا.
  • Technical (تقني): يُنفَّذ داخل أنظمة التشغيل والبرمجيات وأجهزة الحماية — مثل صلاحيات نظام الملفات وجدران الحماية.
  • Physical (فيزيائي): أجهزة تضبط الوصول للمبنى والمعدات — مثل الأقفال والكاميرات والحواجز.
  • Managerial: gives oversight of the system — e.g. policies and risk-management procedures.
  • Operational: relies on a person for implementation — e.g. security training, manually verifying policy compliance.
  • Technical: implemented in operating systems, software, and security appliances — e.g. file-system permissions and firewalls.
  • Physical: devices that mediate access to premises and hardware — e.g. locks, cameras, barriers.

مثال يوضّح التداخل: سياسة الوصول للمستندات managerial، والتحقّق من تطبيق الصلاحيات فعليًا operational، وصلاحيات نظام الملفات نفسها technical — نفس الموضوع، لكن أربع زوايا مختلفة.

An example showing the overlap: a document access policy is managerial, checking that permissions are actually applied is operational, and the file-system permissions themselves are technical — the same subject, seen from different angles.

تصنيف الفئة يوجد فيه تداخل طبيعي دائمًا — الهدف من التصنيف ليس دقة رياضية، بل مساعدتك تقيّمين قدرات مؤسستك مقارنة بأطر العمل وأفضل الممارسات.
There's always natural overlap in category classification — the point isn't mathematical precision, it's helping you assess your organization's capabilities against frameworks and best-practice guides.

الأنواع الوظيفية للضوابط الأمنية

Security Control Functional Types

النوع الوظيفي يصف الغرض من الضابط، لا طريقة تنفيذه

The functional type describes a control's purpose, not how it's implemented

النوعالوصفيعملأمثلة
TypeDescriptionOperatesExamples
Preventiveيقيّد الوصول غير المصرَّح به فيزيائيًا أو منطقيًاقبل الهجومسياسة الصلاحيات، التشفير، الجدار الناري، الأقفال
PreventiveRestricts unauthorized access physically or logicallyBefore an attackPermissions policy, encryption, firewall, locks
Detectiveيكتشف محاولة أو نجاح اختراقأثناء الهجومأجهزة الإنذار، المراقبة، التحقق من سلامة الملفات
DetectiveIdentifies attempted or successful intrusionsDuring an attackAlarms, monitoring, file verification
Correctiveيستجيب للحادثة ويصلحها وقد يمنع تكرارهابعد الهجومسياسات الاستجابة للحوادث، النسخ الاحتياطي، إدارة التصحيحات
CorrectiveResponds to and fixes an incident, may prevent recurrenceAfter an attackIncident response policies, data backup, patch management
Directiveيفرض قاعدة سلوك معيّنة—سياسة استخدام مقبول، لافتات تحذيرية
DirectiveEnforces a rule of behavior—Acceptable use policy, warning signage
Deterrentيُثبّط الاختراق نفسيًا دون منعه فعليًا—كاميرات ظاهرة، لافتة "موقع مراقَب"
DeterrentPsychologically discourages intrusion—Visible cameras, "site under surveillance" sign
Compensatingبديل لضابط أساسي غير متاح، غالبًا لأغراض الالتزام بإطار عمل—مراقبة يدوية إضافية عند تعذّر تطبيق ضابط تقني
CompensatingSubstitutes for a principal control that isn't available, often for compliance purposes—Extra manual monitoring when a technical control can't be applied
الفئة الأولى الثلاثية (Preventive → Detective → Corrective) لها ترتيب زمني واضح مرتبط بالهجوم: قبل → أثناء → بعد. أما الثلاثية الثانية (Directive, Deterrent, Compensating) فليس لها ترتيب زمني، وترتبط أكثر بالسياسات والالتزام. سؤال شائع: "ما نوع الكاميرا الظاهرة بدون مراقبة فعلية؟" ← Deterrent، وليس Detective، لأنها لا تكتشف الحادثة فعليًا — فقط تُخيف المهاجم.
The first trio (Preventive → Detective → Corrective) has a clear timeline tied to the attack: before → during → after. The second trio (Directive, Deterrent, Compensating) has no timeline and relates more to policy and compliance. Common question: "What type is a visible camera with no active monitoring?" ← Deterrent, not Detective, because it doesn't actually detect the incident — it only discourages the attacker.

الأدوار والمسؤوليات ووحدات الأعمال الأمنية

Security Roles, Responsibilities & Business Units

من يملك المسؤولية النهائية، ومن ينفّذ فعليًا

Who holds ultimate responsibility, and who actually implements

  • Chief Information Officer (CIO): المسؤول الأعلى — إداري في الأساس.
  • Chief Security Officer (CSO): يجمع بين الجانب الإداري والتقني للأمن.
  • Information Systems Security Officer (ISSO): دور غير تقني بحت، يتعلق بالمساءلة والالتزام (due care / liability).
  • Chief Information Officer (CIO): overall responsibility — primarily managerial.
  • Chief Security Officer (CSO): combines managerial and technical responsibility for security.
  • Information Systems Security Officer (ISSO): a non-purely-technical role tied to accountability — due care / liability.

المسؤولية عن الأمن قد تحتاج توضيحًا عندما توجد وظيفة أمنية متخصصة إلى جانب مسؤوليات مدراء الأقسام المختلفين — لتجنّب التداخل أو الفجوات في التغطية.

Responsibility for security may need clarifying when there's a specialist security function alongside the responsibilities of different department managers — to avoid overlap or coverage gaps.

الكفاءات الأمنية الأساسية التي يُتوقَّع من فريق الأمن إتقانها:

Core information security competencies expected of a security team:

  • تقييمات المخاطر والاختبارات (risk assessments & testing)
  • تحديد ومصادر وتركيب وتهيئة الأجهزة والبرمجيات الآمنة
  • ضبط الوصول وصلاحيات المستخدمين
  • مراجعة السجلات والأحداث (auditing logs and events)
  • الاستجابة للحوادث والتقارير
  • استمرارية الأعمال والتعافي من الكوارث (BC/DR)
  • برامج التدريب والتوعية الأمنية
  • Risk assessments and testing
  • Specifying, sourcing, installing, and configuring secure devices and software
  • Access control and user privileges
  • Auditing logs and events
  • Incident response and reporting
  • Business continuity and disaster recovery
  • Security training and education programs

وحدات الأعمال الأمنية — كيف تُنظَّم الوظيفة الأمنية داخل المؤسسة عمليًا:

Security business units — how the security function is organized in practice:

  • Security Operations Center (SOC): الفريق المسؤول عن المراقبة المستمرة والاستجابة للتنبيهات الأمنية.
  • DevSecOps: دمج الأمن ضمن دورة التطوير والتشغيل من البداية (Development + Security + Operations)، بدل إضافته كخطوة أخيرة.
  • Cyber Incident Response Team (CIRT): فريق متخصص للتعامل مع الحوادث الأمنية عند وقوعها.
  • Security Operations Center (SOC): the team responsible for continuous monitoring and responding to security alerts.
  • DevSecOps: embedding security into the development and operations lifecycle from the start (Development + Security + Operations), instead of bolting it on at the end.
  • Cyber Incident Response Team (CIRT): a specialized team for handling security incidents as they occur.
لخّصي الدرس بهذا الترتيب الذهني: CIA Triad (ماذا نحمي) ← NIST CSF (كيف ندير الحماية) ← Access Control / IAM (من يدخل) ← فئات وأنواع الضوابط (كيف نطبّق ونصنّف) ← الأدوار والوحدات (من ينفّذ). هذا التسلسل يتكرر منطقيًا في معظم مواضيع الشهادة.
Summarize the lesson with this mental order: CIA Triad (what we protect) → NIST CSF (how we manage protection) → Access Control / IAM (who gets in) → control categories & types (how we apply and classify) → roles & units (who implements). This sequence recurs logically across most of the certification's topics.
